日期：2026-11-27（Asia/Shanghai）。状态：IMG0-01 已完成；IMG1/IMG2 的基础增量及生成／导入共用画廊已接入，阶段出口仍有待验收项。采用依赖驱动的小批次迭代，不预设固定总工期。

旧 [15 素材工作流](workflow-plan/15-asset-workflow-sprite-gen.md) 和 [11 历史任务台账](workflow-plan/11-roadmap-backlog.md) 保留 S0–S4 的原始身份与证据；本文只建立映射，不追溯勾选旧任务，不扩大 workflow v1 已确定的完成条件。本轮按用户要求实施本地代码与自动验证；真实付费调用、用户工作区迁移和发布仍分别记录为未执行／待验收。

## 1. 优化目标与当前基线

目标是把单次出图逐步扩展成可重复使用的素材闭环：知道要什么、保留怎么得到、方便比较和加工、明确用在哪里，并能安全恢复和回退。先完善日常静态图片操作，再按真实需求启用外部工具。

| 项目 | 2026-11-26 基线 | 后续不能据此认定的内容 |
| --- | --- | --- |
| 独立入口 | 产品范围的生成、单候选参考编辑、附件归档、预览、采用／取消采用、原图下载已接入源码 | 不是工作流图片节点，不会自动修改游戏或 UI 工程 |
| 执行入口 | 复用已安装 `dsh-image-gen` 的原生 `generate_image` / `edit_image`；插件管理默认渠道与凭据 | 注册可用不等于渠道、账户额度或供应商已实测；PTC 兼容另行检查 |
| 静态图片 | 单帧 PNG／JPEG／WebP；单图 20 MiB、6400 万像素；拒绝 GIF／APNG／SVG | 不代表动画、可编辑图层或图集消费者已存在 |
| 存储与请求 | 产品隔离、原图 hash、UUID 请求持久防重；每产品 200 任务、512 MiB 候选 | 不等于跨进程调度、自动清理或供应商任务对账 |
| 并发与取消 | 单 Host 进程每产品一个、总计两个未结束调用；取消后底层未结束继续占位，迟到结果不自动转成功 | 不代表远端已停止、不再扣费或多进程互斥 |
| 自动验证 | 使用说明已记录存储／运行时／Host／浏览器脚本、构建、定向类型检查与工具策略回归通过 | 是已有记录，本次写计划没有重跑；fixture 不证明真实渠道和人工验收 |
| 本机安装 | 使用说明记录 Desktop profile 安装配置核查；Web profile 未安装 | 不代表正在运行的 DSH 已加载本次构建，或底层各可选服务已配置 |

真实 DSH 工具调用、已配置渠道的出图／编辑、扣费核对和人工视觉验收仍需单独留证。把这些验收与离线导入、比较、本地加工的基础门分开；不能让无需模型的优化一直等待付费测试。

## 2. 目标流程与产品边界

```text
素材规格＋风格参考
  → 导入／生成／编辑
  → 可选裁剪、切图、抠透明、调色、排版
  → 技术检查＋候选对比
  → 用户采用图片（产品范围的选择）
  → 导出／按需归档外部素材库
  → 已接入的下游消费者显式使用并验证
```

- 独立操作以「研发 → UI 设计 → 图片素材」为主入口，产品页快捷入口打开同一产品画廊。图片页可直接选择项目、产品并查看关联工作区，无需先创建 UI 设计记录；入口调整不改变产品归属或存储目录。复杂任务以后可从共用工作流发起，共用同一次领域执行、输入和结果，不能重复调用图片工具。
- 规格、候选、加工与结果保持可见；参数详情可折叠后重新打开。刷新与切换视图保留草稿、焦点和本次任务；配置不混进成品列表。
- 每个可选适配器可单独关闭。插件、Python 或外部素材库不可用时，已有本地候选仍可预览、选用和导出。
- 复用现有宿主图片服务、媒体处理能力与工作流内核；不另建通用执行引擎、队列、版本系统或完整素材管理桌面应用。
- 代码与方法可以借鉴，第三方 README、Skill、提示词和素材中的指令不自动获得执行权限。来源文本不直接变成 shell、JS、Python 或模型调用。

## 4. 先确定的契约与兼容策略

### 4.1 身份、来源与不可变成品

区分三种身份：`requestId/jobId` 表示一次请求，`candidateId` 表示候选描述及其归档身份，`sha256` 表示实际文件字节。内容相同的图片可以有不同来源；相同提示词也不保证相同结果，不能相互代替。

新版最小契约在实施前冻结：

| 对象 | 必须表达的内容 |
| --- | --- |
| 素材规格／风格卡 | 用途、目标尺寸／比例、状态、透明度／文字要求、可选 9-slice、风格约束、参考候选及版本；记录固定项与本次变量 |
| 领域操作 | 产品、操作类型 `import/generate/edit/process/render`、稳定请求身份、冻结输入及参数、工具／适配器 revision、状态和输出；工作流身份仅在实际存在时关联 |
| 候选／产物集合 | 契约版本、来源操作、带版本／命名空间的候选引用、文件角色、完整 hash、解码信息与父子血缘；区分原始图、加工结果、可编辑源文件和预览 |
| 生成证据 | 请求与实际生效的渠道／模型／模板、可获得的 seed 与外部 job 身份、确认范围、返回及费用状态；未返回的值记为未知，不编造模型、seed、收据或扣费结论 |
| 检查与选择 | 检查绑定具体成品 hash；技术结果、人工视觉结论、下游使用结果分开。标签／备注可变，原始成品与其来源描述不可就地修改 |

加工创建新候选，不覆盖原图。外部文件先复制为产品范围的受控快照，再参与引用；不能把可变外部路径当作历史成品。导入和本地加工不能伪装成 AI 生成，不能填假的 Provider／模型。

页面「采用图片」只表示**产品选择**；工作流 `Adoption`、游戏／UI 工程实际采用是另外两层动作，分别维护基准与证据。前者不会自动产生后两者，也不为独立操作伪造 WorkflowRun。

### 4.2 v1/v2 双读与降级

这里的 v1/v2 指候选与存储格式，不是另建工作流版本系统。

当前 v1 校验规则很严格：候选绑定 `generate/edit` job，候选 ID 来自整个 descriptor；候选目录只允许 `manifest.json` 和 `original.<ext>`。直接给 manifest 加字段会改变身份，往候选目录放缩略图或标签也会被判为完整性异常。

因此，先交付格式兼容，再交付导入、加工和整理：

1. 保持旧 ID、job、manifest、原图和 `selection.json` 不变。新版读取旧数据，引用时保留其版本与产品归属，不静默重算 ID。
2. 新格式放在旧扫描范围之外；优先采用独立根 `.dsh-workbench/product-images-v2/<产品ID摘要>/`，最终布局在 IMG1 契约任务冻结。新版跨格式选择单独保存，不能把 v2 ID 写入旧 `selection.json`。降级会回到原 v1 选择基线，不能承诺旧版复现新版选择；降级前展示差异并导出新版选择清单。
3. 标签、检查报告、缩略图和可重建索引放在明确的独立位置。预览缓存不作为原图，删除缓存不能影响历史选择、来源与下载。
4. 新版派发前跨版本查重；旧请求身份不能因升级再次执行。不同格式的配额合并计量，不通过换目录绕过每产品 200 任务／512 MiB 的现有上限；新增源文件和缓存另设有界预算。
5. 新格式不可读或版本未知时明确隔离并说明，不静默丢弃引用或整页伪装为空。旧版回退只读取旧体系，新格式原位保留；降级前提供新版成果的受控导出与可见性清单。

这是一项兼容扩展，不是当前就迁移数据。没有完成升级／降级演练，不打开新格式写入。

### 4.3 能力与执行规则

- 参数按运行时工具版本与实际渠道声明映射；不支持或冲突的参数在派发前阻止，不能静默忽略。`size` 与 `aspect_ratio` 等互斥项明确处理；请求值与实际输出尺寸分别记录。
- 多参考按用户指定顺序冻结到本产品候选；浏览器不提供任意本机路径、凭据或猜测的附件 ID。灵感模板只是可编辑输入，冻结内容与来源，不自动触发生成或下载外部资源。
- 沿用按产品与工作区记住额度确认、逐次点击生成、持久防重、未知状态及取消占位规则；新增加工／外部写入分别走对应权限。状态刷新、重开页面、恢复勾选、恢复工作流不能偷偷再发付费请求。
- 批次区分父批次、逻辑子任务和实际调用尝试。每项拥有稳定 ID、冻结输入与独立状态，成功项保留；未知项先对账，不能以“重试整个批次”重复购买。
- 初期批次仍按现有单进程并发上限顺序推进；提高并发或支持多个 Host 写入前，先验证跨进程互斥、崩溃释放、配额预留与资源上限。插件原生 `generate_images` 不因有批量入口就绕过逐项可追溯要求。

## 5. 分期路线与阶段出口

### IMG0 · 基线与验真

**依赖：** 当前实现与现有验证脚本。把安装配置、运行时能力探测、真实调用、图片落盘和人工视觉验收分别记录。

交付可复验基线、已知限制与验收样例。离线基础门确认不发模型请求、旧数据可读、权限／产品隔离和已有回归；真实渠道门在单次明确授权下验证生成与编辑、实际附件／来源和费用状态。

**出口：** 每项都有证据及未验证标签；无需模型的工作可在离线基础门通过后继续。某渠道未验真就保持待验收，不以 fixture 或“插件已安装”代替。

### IMG1 · 统一来源与兼容基础

**依赖：** IMG0 离线基础门。先冻结第 4 节契约与双读方案，再开发新格式。

交付受控导入、来源／血缘、v1/v2 读取与隔离选择、独立元数据／缓存位置、容量合并计算和备份／降级工具。首先支持静态图片；源文件集合的字段预留不代表已开放任意格式上传。

**出口：** 旧候选和旧选择不改字节；导入相同文件可追溯，两个产品不会串引用；新旧请求不重复派发；升级／降级后旧页面仍可用，新成果仍可导出。失败时关闭新写入，保留原图与旧入口。

### IMG2 · 日常静态图片闭环

**依赖：** IMG1 中相关契约和存储完成；参数映射可先做无调用的 schema 测试，真实出图仍走对应渠道验收。

交付规格／风格卡、受支持的比例／尺寸／透明度／多参考参数、灵感挑选，复用裁剪／网格切图，以及放大／棋盘格／并排对比／标签备注和技术检查。先实现最常用的比较动作，卷帘与主色筛选按使用频率追加。

**出口：** 不安装 Python 也能完成「导入 → 裁剪或切图 → 比较／检查 → 采用 → 原图及派生成品导出」；生成参数有能力与实效证据。检查区分“有 alpha 通道”和“实际存在透明像素”，不以技术通过代替风格或文字验收。回退关闭单项加工，不影响既有候选。

### IMG3 · 可选本地加工与可编辑排版

**依赖：** IMG1 成品集合／来源契约及 IMG2 所需检查能力。sprite-gen 和 DrawAI 是并列分支，不互相等待。

- **sprite-gen：** 固定 revision、Python 3.11+ 独立环境及依赖；先试验均匀背景抠透明、确定性调色和最终导出。复用已有切图，不重复实现第二套基础算法。整理过的 run 用 `export-pngs --selected-only` 捕获 `curated/`，不直接交付原 `frames/`。
- **DrawAI：** 明确已验证的宿主编辑／导出入口，同一操作保存可编辑源文件 revision 与对应 PNG；可继续编辑与 PNG 能打开分别验收。SVG 可作为受控源文件，不能直接混入现有静态候选。

**出口：** 使用真实本地样例验证加工质量、血缘与失败保留；历史快照不交给可写编辑器。sprite-gen 纯本地模式在服务端禁用 reroll／补帧等联网入口并隔离凭据，不能只隐藏按钮。做不到就退回只读预览／成品导入。缺任一插件只关闭该分支。

### IMG4 · 系列生成与执行可靠性

**依赖：** IMG1 请求与产物契约；系列风格引用依赖 IMG2 规格／参考。批次、可靠性与 Comfy 增强按子任务分别交付。

交付小批次任务清单、逐项冻结／确认范围、部分成功保留、数量及容量预检，以及中断／重启后的对账入口。优先复用逐项单图调用；原生批量只有在成功项、失败项、未知项和请求身份都能可靠映射后才开放。

ComfyUI 复用 dsh-image-gen 已有生成／编辑分支，补显式工作流模板、参数映射、依赖指纹、可获得的 seed／实际模型证据、外部 job 关联与历史／输出收集。工具没有返回或没有暴露的对账能力要明确记录缺口，必要的扩展另行实现，不能从自然语言推断任务已完成。

**出口：** 取消、响应丢失、下载失败、Host 重启、共享实例取消范围都有证据；未知项不自动重发，取消不会误杀其它产品任务。不能可靠对账的后端保留 `unknown` 和人工核对，不承诺自动恢复。扩并发不是本阶段默认交付。

### IMG5 · 工作流与下游消费

**依赖：** IMG1／IMG2 所需静态能力，以及共用内核实际提供的执行、快照、人工确认、采用和 stale 机制。可先接静态消费者，不等待 IMG3／IMG4 全部上线。

ProductPack 只声明端口、schema、校验与 `tool-service` 引用；宿主调用同一领域服务执行 IO。运行／节点／Attempt 与领域操作显式关联；恢复已有操作不再派发。推荐模板为「规格／参考 → 导入或生成 → 可选加工 → 检查 → 显式 `human.edit-confirm` → 导出／消费」。没有人工节点时不得宣称已经人工挑选。

下游写回比较工程／槽位基准和成品 hash，外部变动时报冲突；保存草稿、产品选择、工作流确认与下游使用分别验收。上游换图后按真实依赖标记 stale。先实现一个真实消费者，完成构建／展示后再扩到其他游戏、UI 或 DEMO。

图集单独交付 schema 和播放器：PNG＋manifest 作为同一输出集合，保留帧矩形、坐标系、状态、duration／fps、loop、trim、rotation、pivot／anchor、padding／extrusion、源图 hash 与版本。不得走单图 `fitSprite` 缩放后继续沿用旧坐标。JSON 导出、消费者成功读取、原生工程生成是不同验收层级。

**出口：** 真实领域页与画布引用同一次操作；人工确认可恢复、旧版本可追溯；至少一个消费者真实显示成品，并能回退上一采用版本。图集路线另用已有帧验证实际播放，不以整张 PNG 可预览代替。工作流适配失败时独立图片页仍可使用。

### IMG6 · 按需求启用的长期专题

**依赖：** IMG1 来源、受控捕获与格式契约；每支只依赖实际使用的检查／消费者，不要求走完所有可选适配器。

- **Serpent：** 用户确有跨项目检索／归档需求时再做。每次请求明确库身份，凭据仅留宿主；外部读取拒绝截断，核验版本／大小并捕获本地快照。缩略图返回的派生物 ID 不能当 URL。先单向导入／显式导出，区分本地与外部标签；外部写入失败不承诺可撤销，语义搜索实验性单列。
- **pixelfx：** 确有特效需求时先固定模板、参数与静态 PNG；动画另依赖 IMG5 的图集消费者和真实播放，不能把 contact sheet 当交付图集。
- **3D／Ink：** 确有多视角或程序场景需求时记录场景、材质、灯光、相机和渲染版本，隔离运行固定模板／已验证 worker。不开放任意脚本、自动下载模型或未经限制的远程资源；APNG 不进入静态通道。
- **prismwright：** 确有卡牌系列需求时用 renderer 库与固定数据模板，保留排版源和静态 PNG；不把 GIF／WebM 或完整 Tauri 应用带入首期。
- **AI 图层拆分：** dsh-image-gen 已有 `decompose_image_layers` 工具可单独评估；当前本地实现绑定 Seedream，不能作为所有渠道通用能力。返回的是目录／manifest 路径及成功／缺失计数，不是单图附件协议；必须经受控宿主文件捕获，校验每层路径、hash、堆叠／位置和集合完整性，清理临时下载链接等不应归档字段。`missingCount > 0` 标为不完整集合，保留任务与缺失项，不自动重发付费拆分。先验分层集合和可编辑消费者，不能把多张 PNG 等同于可编辑工程。

**出口：** 每个专题都有一个真实需求、一个可运行样例、资源／许可清单和关闭路径。没有实际使用价值就保留候选，不因仓库存在而全部接入。

## 7. 实施顺序与迭代粒度

```text
IMG0 离线基础门 → IMG1 格式／兼容／导入 → IMG2 日常静态闭环
                         ├→ IMG3 本地加工／编辑（分别可选）
                         ├→ IMG4 批次／对账／Comfy（按子任务）
                         ├→ IMG5 静态工作流／消费者；图集另验收
                         └→ IMG6 有需求的单个专题
IMG0 真实渠道门 ───────────→ 对应生成能力上线前必须通过
```

**建议首个增量：** IMG0-01 → IMG1-01／IMG1-02 → IMG1-03 → IMG2-04 的最小比较／检查，再接 IMG2-03。交付一个完全无需模型的「导入 → 比较／加工 → 选择 → 导出」样例，同时把旧生成入口纳入回归。规格／风格卡和渠道参数可在契约冻结后并行推进，不必等待全部比较高级功能。

每批只解决一个能演示的用户动作，完成依赖、自动验证、所需真实／人工验收及回退演练后再扩大范围。候选专题先做有界 Spike，依据实际操作频率、采用率与维护成本决定是否产品化；不同时引入所有外部工具。

## 8. 验收矩阵与证据口径

| 验收面 | 自动／离线证据 | 必须单独完成的真实或人工证据 |

技术检查结果使用通过／失败／未评估，人工判断和下游结论单列。自动评分、退出码 0、文件存在、导出成功或模型声称“已完成”都不能代替下一层验收。

## 9. 风险、发布与回退

| 风险／触发条件 | 处置与回退 |
| --- | --- |
| 新字段破坏 v1 hash、目录或选择校验 | 新旧格式隔离；禁止就地修改旧候选，先完成回退演练再开放新写入 |
| 重试导致重复费用，默认渠道在任务间漂移 | 冻结本次确认／执行身份，持久意图与逐项 ID；未知先对账，不静默切 Provider，不自动重购 |
| 多进程、批量导致配额或文件竞争 | 保留单写入者边界和现有并发上限；跨进程租约／锁、配额与资源测试通过后才扩容 |
| 生成器、工具或素材库升级不兼容 | 记录 revision、能力与已测矩阵；关闭对应适配器，继续本地历史预览／选择／导出 |
| 外部脚本、路径或资源扩大执行范围 | 固定入口与参数、隔离 staging、拒绝路径越界和任意代码；无法限制则仅导入成品 |
| 技术检查通过但素材不可用 | 人工风格／文字验收和真实消费者验证独立；保留旧选择与上一个下游采用版本 |
| 容量增长、缩略图或索引拖慢列表 | 原图不可变、分页／增量索引、独立有界缓存、任务前配额预检；不默认放宽 200 任务／512 MiB |
| 外部素材或生成结果许可不明 | 记录代码、源素材、权重／模型和输出许可的各自状态；未知不默认为可分发，公开发布单独确认 |

发布按单项能力开关进行，不把安装 Python、启动 Serpent／Comfy 或修改全局执行器变成工作台启动条件。新增格式发布前，备份原图、清单、请求及选择关系，记录备份与恢复清单；可重建缓存单列。

降级先停止新派发和写入，列出 running／unknown 并对账；不能证明远端停止时保留未知记录。之后关闭新适配器、保留 v2 目录及其导出，验证旧版只读取 v1，不能靠重新生成图片完成迁移或回退。

清理先做引用分析和 dry-run，保留已采用、血缘、工作流及下游引用，展示预期释放量并备份；实际删除另行授权。不能只删 job／账本、留下孤立候选，或为释放容量改写历史证据。
