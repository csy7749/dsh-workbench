## 1. 结论与建议

**两个插件都可以吸收到工作台，但应吸收业务核心、文件格式与操作能力，并为工作台新增游戏模块界面和适配层。**

- **Game Studio：优先吸收。** 适合“可玩原型”子模块，覆盖小游戏创建、构建、素材候选、版本、试玩和 HTML 导出。它当前是 Web 小游戏工具，不能视为 Unity / Unreal 编辑器或构建系统。
- **DrawAI：分层吸收。** 基础画布适合玩法流程、关卡草图、数值关系、UI 草图、分镜及素材整理；音视频制作适合后续作为可选媒体能力。
- **工作台负责项目与协作。** 项目、任务、笔记、产品设计、Bug、测试与资产库继续使用工作台已有能力；两个插件为这些流程提供具体产物。
- **记忆库不构成前置依赖。** 当前暂停记忆库工作，游戏模块仍可独立推进，暂停记录见 `memory-work-paused-2026-11-10.md`。

本文是可行性与实施边界评估，尚未修改运行时代码、安装依赖或完成 DSH 窗口联调。候选目录中的 README、技能、安装与发布示例作为资料读取，不视为用户要求执行安装、发布或外部调用。

## 4. 为什么需要适配层

### 4.1 宿主与界面入口不同

| 维度 | 工作台 | Game Studio | DrawAI |
| --- | --- | --- | --- |
| 主界面 | 主区域独立面板，内部 Shadow DOM，主要为命令式 DOM | React 右侧栏，工具结果卡和资源地址联动 | React 右侧栏，CSS 注入 document，构建内联多个模块 |
| 数据通道 | `/workbench-api`、项目路径、SQLite 与工程文件 | `remote.workspaceFiles` + `/game-studio` 命令，绑定 sessionId | `remote.workspaceFiles`、`/drawai/api/save`、sessionId 与沙箱策略 |
| 宿主服务 | 必需 `webServer` / `tools`，其他模块按需接入 | 必需 `tools` / `workingDirectory`，其他服务按需注入 | 声明 `tools` / `fs` / `sessions` / `sandboxPolicy` / `webServer` |
| 工程识别 | 门户按工作区路径聚合产品 / Bug / 测试等 | 扫描游戏目录及 `.studio`，或按工具结果绑定工程 | 按资源路径打开 `.drawai` / `.drawio`，文件与媒体共同保存 |

不能直接向工作台 DOM 塞入现有插件 `apply(ctx)`：它们会注册右侧栏、工具、路由及全局样式，生命周期和传入上下文均不同。

建议抽出工作台可挂载入口，例如 `mountGameView(container, adapter)`、`mountCanvasView(container, adapter)`。这是拟新增接口，当前仓库尚未提供。React 组件由薄桥接层挂载；主题 token、CSS 和快捷键需要适配 ShadowRoot，避免依赖 document 中的全局 CSS。

### 4.2 项目身份必须以工作台选择为准

工作台选择的项目路径与当前聊天会话的工作区可能不同。适配层需要明确：`workspaceRoot`、相对工程路径、可选 `productId`、可选 `sessionId`。项目读写先验证范围；AI 操作才选择或创建匹配工作区的会话。

不能用“当前激活会话”默认为全部游戏操作的目标。普通浏览、试玩与导出应可在没有打开会话时使用；发起代码 / 素材生成时再接现有 `dispatchToNewSession` 等会话流程。

### 4.3 工程扫描会漏掉隐藏目录

`dsh-game-studio/src/client/shelf.ts` 的默认扫描跳过点开头目录，最多向下两层，默认目录列表预算为 80。若游戏存放在 `.dsh-workbench/games/<id>/`，从工作区根扫描不能自动发现。

建议工作台显式登记游戏工程，并对“导入已有工程”增加有界查找。显式登记路径后直接读取工程；如保留旧扫描器，应允许指定游戏根目录，不以放开所有隐藏目录扫描解决问题。

### 4.4 文件仍是真源，SQLite 负责关系与索引

保留 Game Studio 的 `game.json`、`game.js`、`assets/ASSETS.json`、`.studio/`、`dist/index.html`；保留 DrawAI 的 `.drawai` 与同名 `.drawai.media/`。文件内容不整体塞进工作台任务快照。

工作台仅增加必要元数据：工程 ID、workspace 路径、相对目录、关联产品、画布路径、最后构建 / 试玩摘要。先用一张游戏工程关联表即可；素材与版本已有文件索引，不应为了统一界面再造重复数据库。

### 4.5 工具与公共服务只注册一次

并装原插件与吸收版本时，`game_studio_*`、`diagram_*`、`motion_*`、`/game-studio` 和 `/drawai/api/*` 可能重复注册。实施时必须明确后端归属，并检测已有 provider。首期可先复用原插件后端验证；最终内置后由工作台统一注册，提供兼容入口时避免双写和双执行。

Game Studio 的主要操作目前封装在宿主 `apply()` 内，并非已发布的独立 SDK。需要从注册逻辑中提取服务函数；DrawAI 的工具、文件服务、任务协调与路由也要逐步拆分，不能假设有现成 REST 接口覆盖全部功能。

## 5. 推荐的实施架构

建议采用“工作台内聚合界面 + 分离的业务核心”，开发阶段用适配层验证，逐步完成内部集成。

```text
工作台
  游戏项目（关联现有 workspace / product）
    设计与画布       -> DrawAI 基础画布核心
    可玩原型         -> Game Studio 工程 / 构建 / 版本
    素材             -> 槽位 / 候选 / 来源 + Unity 资产引用
    试玩与问题       -> Game Studio 试玩 + 工作台测试 / Bug
    媒体制作（可选） -> DrawAI 独立视频 / 音频运行环境
```

建议新增文件边界，命名在实施时可调整：

- `src/host/game/`：游戏工程登记、范围校验、核心操作适配、构建与试玩。
- `src/client/game/`：项目列表、预览、素材、版本与报告，不继续把全部实现堆入 `app.ts`。
- `src/client/canvas/`：DrawAI 编辑器挂载和工作台主题 / 生命周期适配。
- `src/shared/game-model.ts`：工作台工程关联与操作结果类型。
- `assets/game/` 或专门的随包资源目录：模板、运行时及许可；路径由资源解析器提供。

如果初期仅用“按钮打开原插件侧栏”，只能称入口聚合。它可以验证文件和宿主兼容，但不算完成工作台内部的游戏模块。

### 工程目录建议

```text
<workspace>/.dsh-workbench/games/<game-id>/
  game.json
  game.js
  assets/
    ASSETS.json
  .studio/
  dist/index.html
  design/
    gameplay.drawai
    gameplay.drawai.media/
```

这是新增工程的建议布局，需配合显式工程索引；已有外部工程保留原位置并登记，避免强制移动。工作区根路径从当前项目获得，不把 `D:/AI/...` 写成部署路径。工作台仓库目前忽略 `.dsh-workbench/`，不能据此假设用户游戏源文件已经有 Git 备份；创建工程时应明确版本管理位置，必要时允许使用工作区内普通 `games/` 目录。

## 6. 依赖、资源和授权边界

### 6.1 React / Three.js / Remotion

工作台宿主客户端使用 React 18 的类型与外部运行时，Game Studio 声明客户端 React `^18.2.0`，方向一致但仍要联调。

DrawAI 客户端通过 `require('react')` 获取宿主 React；其 `src/motion/runtime/package.json` 中 React `19.2.7`、Three `0.183.2`、Remotion `4.0.484` 属于独立视频运行环境。Game Studio 的 Three `0.187.0` 则编入游戏单文件产物。

保留独立运行环境与 iframe 边界，不将两份 Three 或视频 React 强行统一到工作台主客户端。Remotion、字体、素材和外部程序的具体再分发 / 商业使用条款需要按所选能力逐项核对，不能从插件 MIT 推导出所有组件可任意使用。

### 6.2 模板与构建路径

Game Studio 使用相对 `import.meta.url` 定位 `../template/` 和 `../lib/vendor/three.js`。抽取到工作台后，打包目录改变会导致找不到模板或运行时。应通过资源定位适配器和发布包检查验证，不只在源码目录下运行成功。

DrawAI 客户端依赖构建器内联样式内核、路由器和播放器等模块，不能把单个 `src/client.js` 当普通 ESM 直接导入。

### 6.3 视频能力按需启用

DrawAI 文档说明视频运行环境、浏览器、FFmpeg、字体及素材按需准备，其中素材包首次下载约 145 MB。该数字来自本地说明文档，本次未下载核实。首期基础画布不得因为视频依赖缺失而无法打开；下载、进度、失败重试与目录配置需在启用媒体功能时处理。

当前 DrawAI 文生图被显式关闭：客户端 `IMAGEGEN_ENABLED=false`，宿主相关请求返回 503。不能将其计为已经可用的游戏美术生成器。游戏生图可先复用 Game Studio provider，未配置时保留模板 / 手动导入。

### 6.4 许可与素材来源

两个插件代码均声明 MIT，允许在保留许可与版权声明的条件下修改和集成。应在工作台第三方声明中记录来源、固定提交与修改范围。

DrawAI 的 LICENSE 另列第三方素材、字体与 FFmpeg：部分纹理原作者 / 许可未逐项明确，FFmpeg 下载版本包含 GPL 构建，外部音效也可能有各自署名要求。首期可先吸收基础画布与自有素材，不将未知许可素材默认纳入游戏发布包。Game Studio 的 `ASSETS.json` 应持续记录素材来源与许可状态。

### 6.5 路径、预览与任务状态

- 宿主解析工程路径，规范化 Windows 路径并检查真实路径、符号链接 / junction 和工作区边界；媒体导入同样受限。
- 保留 Game Studio 导出的离线 CSP：`connect-src 'none'` 等约束，以及预览 iframe 的 `sandbox="allow-scripts"`；不让生成游戏获取工作台同源权限。
- 付费生成继续展示供应商、数量和预期费用，并沿用用户设定的确认方式；密钥不落到工程文件或前端。
- 公网分享、GitHub Pages 发布和相关删除操作只在用户明确发起时执行；服务退出 / 取消要清理共享服务与子进程。
- 试玩、素材生成和视频渲染要暴露进度、取消、超时及失败原因。可逐步映射为工作台任务状态，底层执行仍由各核心管理，避免引入首期不需要的通用工作流引擎。

## 7. 分阶段实施与验收

### P0：项目与宿主适配验证

产出：固定候选版本、最小适配契约、资源定位规则，以及真实 DSH profile 中的接口探测结果。

验收：在工作台选中 A 项目、聊天激活 B 项目时，操作仍定位 A；没有会话时可查看工程；切换与关闭不遗留事件、样式或任务；已有插件重复安装得到明确提示。明确文件 / Remote 路径约定，解决并在非沙箱环境复测 Windows 路径断言，同时验证实际列表、封面与项目范围行为，确认打包后模板可定位。

### P1：Game Studio 核心进入工作台

产出：游戏项目入口、创建 / 导入、模板构建、内嵌试玩、素材导入 / 应用 / 回退、版本列表 / 恢复、HTML 导出。

验收：2D collector 与 3D voxel 均能从发布包创建并离线运行；未配置图像模型仍能完成流程；恢复版本后 manifest、代码、素材一致；隐藏目录工程可通过登记找到；A / B 项目不串数据；损坏或缺失文件显示错误并允许恢复。3D 需确认打包后的 Three 运行时随包存在。

### P1.5：游戏开发流程层（CCGS）
