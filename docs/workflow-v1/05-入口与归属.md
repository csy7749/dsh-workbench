# 工作流 v1 · 05 入口与归属

状态：**已定（2026-11-15 对话拍板）**。本文回答「工作流挂在哪里」和「一张图归谁」两个问题，取代上一版被否掉的「绑定共享模板」方案。参考对象：ComfyUI 的成熟做法（逐条对照见第 6 节）。

2026-11-19 补充确认并修正：以下两个编辑入口继续保留；「工作流」放在工作台内部侧栏，跨项目汇总运行、待处理和近期历史，工作台门户提供摘要；不在最外层增加与「工作台」同级的按钮。跨项目入口按指定 runId 查看冻结运行，不改变产品图的归属，也不共享可变产品图。产品设计、UI / DEMO、测试 / Bug 逐步接入共用工作流；当前实施范围与验收见 [08 全局工作流入口与研发接入](08-全局工作流入口与研发接入.md)。

## 1. 两个入口，两种事

| | 研发 → 工作流模板 | 产品 → 流程 |
| --- | --- | --- |
| 落点 | `PORTAL_GROUPS` 的 `rd` 组新增一张卡（`src/client/app.ts:235`） | 产品作用域 tab 栏（`src/client/app.ts:1482` 的 `taskSeg`）新增一个 tab |
| 用户问题 | 我要造一套流程，给别的产品当起点 | 这个产品卡在哪、等我确认什么 |
| 对象 | 模板 + 版本（不可变版本表） | 产品自己的图 + 运行 + 产物 |
| 能不能拖节点 | 能（编辑器） | 默认打开画布，可切换到流程进度 |
| 产出 | 模板 v1 / v2 … | 运行记录、冻结定义、导出文件 |

**修正**：图归产品所有，产品页可以直接编辑；2026-11-17 起默认展示画布，当前验收口径见 [07](07-画布产品化补充计划.md)。

## 2. 归属模型：复制即分离

四层，一层只回答一件事：

| 层 | 例子 | 谁拥有 | 共享 | 改它影响谁 |
| --- | --- | --- | --- | --- |
| Pack 词汇表 | `game.rules` / `check.rules` 这些节点类型 | 平台 | 是，带 typeVersion | 所有用它的产品（靠版本兜） |
| 模板 | 「游戏 v1：需求→设计稿→规则→校验→确认→导出」 | 平台 | **复制即分离** | 只有还没复制的产品 |
| 产品图 | A 产品这一份具体流程 | **产品自己** | 否 | 只有 A 的新运行 |
| 运行 | 运行 #12 跑的是哪一版图 | 产品 | 冻结 | 谁都不影响 |

**核心不变量**：不存在一张被多个产品共用的可变图。冲突之所以不可能发生，是因为没有共享的可变对象——不是因为加了锁。

**词汇表与流程分开**：节点类型共享（它是能力，必须统一升级），流程不共享（它是业务，每个产品不同）。上一版把两者混成一层，是那次设计失败的根本原因。

## 3. 产品业务变了改哪里

| 变更 | 改哪里 | 动模板吗 |
| --- | --- | --- |
| 加一步「商业化设计」、把人工确认挪到校验前 | 产品图 | 否 |
| 提示词强调中式玄幻、校验阈值放宽、导出目录换 | 产品图里该节点的 config | 否 |
| 确信别的产品也需要（如「所有游戏线先过合规检查」） | 产品图先跑通，再**保存为模板** | 是，作为经验沉淀 |

**流程改动永远先发生在产品图上。** 模板只能是「已经跑通的东西」的沉淀，不能是「还没验证的想法」的强加。

## 4. 保存为模板（本次新增）

产品图 → 我的模板，一个显式动作，不是自动同步。

### 4.1 动作

产品流程页右上「保存为模板」→ 对话框：

1. 模板名（默认 `产品名 · 图上第一个输入节点标题`）。
2. 适用产线（默认取图的 `line`）。
3. **参数脱敏清单**（关键，见 4.2）。
4. 一句话说明：这套流程解决了什么问题。

保存后写入 `wf_templates`（新版本 v1）+ `wf_template_versions`（不可变快照）。

### 4.2 参数脱敏（不脱敏会串味）

产品图里有业务数据：一句需求原文、导出目录、项目路径、具体数值。直接存成模板，别的产品复制过来会带着 A 的内容，既是污染也可能泄漏。

保存时逐个字段判断，能脱敏的脱敏、不能的列出来让人勾：

| 字段类型 | 处理 |
| --- | --- |
| `input.brief` 的 `text` | 清空，保留 placeholder 提示 |
| `output.publish` 的 `dir` | 清空（导出路径由运行时生成） |
| `input.doc` 的 `path` | 清空，`source` 保留 |
| 生成节点的 `prompt` | **保留**（这是流程知识，不是产品数据） |
| 数值 / 阈值 / 选项 | 保留 |

对话框里显示「将清空 3 个字段、保留 12 个」，可逐条取消勾选。原则：**宁可多提示一次，不要静默带着别人的数据。**

### 4.3 模板的两级

| 级别 | 谁建 | 存哪 | v1 |
| --- | --- | --- | --- |
| 内置模板 | 平台（随 pack 发布） | `src/packs/<line>/templates.ts` | 已有（3 个） |
| 我的模板 | 用户在研发入口或产品页保存 | `wf_templates` 表 | **做** |
| 平台模板 | 从「我的模板」提升 | 同表 `status='published'` | 字段留好，v1 只读 |

### 4.4 模板版本

`wf_template_versions(id, template_id, revision, graph_json, note, created_at)` 不可变。

- 再点「保存为模板」→ 同名则新增 revision，不同名则新建模板。
- 产品图记 `forked_from_template_id` + `forked_from_revision` → 「对比上游」有据可查（v1 可以只显示差异数量，不做合并 UI）。

## 5. 产品流程页长什么样

三栏，默认进度视图：

```text
┌──────────────┬────────────────────────────┬───────────────────┐
│ 运行列表      │ 当前运行的步骤（拓扑顺序）    │ 当前停住那一步的操作区 │
│ ● 进行中 3    │ ① 需求        ✓ 已采用      │ 产物预览           │
│   运行 #12 … │ ② 设计稿      ✓ 已采用      │ 编辑 / 确认并继续    │
│ ○ 等待确认 1  │ ③ 规则 JSON   ● 待确认      │ 保存草稿 / 驳回      │
│   运行 #11 … │ ④ 校验        · 未开始      │                    │
│ ✓ 已完成 8    │ ⑤ 确认        · 未开始      │                    │
└──────────────┴────────────────────────────┴───────────────────┘
```

- 右上角：「画布视图」（只读渲染 + 状态角标）/「编辑这张图」/「保存为模板」/「新建运行」。
- 空状态：没有图时显示「从模板开始」（列内置 + 我的模板）或「空白画布」。**这是首屏，不要给一张空画布。**
- 待确认项同时出现在「行动清单」顶部一条聚合提醒「待我确认 3 项 →」，点进流程页。理由：人不会主动点 tab，人工节点不提醒就会挂着没人管。

### 实现注意

- `taskSeg()` 现在只在 list / timeline / board / matrix 四个视图渲染，加「流程」后点进去这个 bar 会消失 → **提升为项目工作区 bar**，五个视图共用。
- 面板宽度四档（≥1280 / 1180–1279 / 960–1179 / <960 不支持），bar 里已有 4 tab + 今天/全部 + 项目/空间/筛选/排序，第五个一定挤 → 窄屏把「今天/全部」收进筛选，tab 只留图标。
- tab 文案用「流程」（两个字在窄栏更稳）。

## 6. 从 ComfyUI 学什么（逐条对照）

| ComfyUI 的做法 | 对我们 | 决定 |
| --- | --- | --- |
| 工作流就是一份 JSON，可保存 / 导出 / 导入，拖进画布即用 | 产品图也能导出 .json、跨机器搬 | **采纳**，导出即备份，不依赖数据库迁移 |
| UI 格式（带布局）与 API 格式（扁平执行）两份 | 产品图（带布局）vs 冻结运行定义（扁平） | **采纳**，就是 02 的「编译」这一步 |
| 队列：提交即快照，队列列表 + 历史 | 运行 = 队列项，含图快照 + 定义 hash | **采纳**，运行开始即冻结 |
| 缺少节点类型时标红提示，不静默丢节点 | 打开图时列出「缺 capability / pack 版本不符」的节点 | **采纳**（对应 02 的 `node_unknown`，但要前置到打开时） |
| 节点可 mute（停用）/ bypass（绕过） | 「停用节点」：灰色、跳过、连通性沿用 | **只做停用**，bypass 透传语义复杂，v1 不做 |
| 模板浏览器（Browse Templates）内置一堆起点 | 空状态给「从模板开始」 | **采纳**，来源是本产品线的 pack 模板 + 我的模板 |
| 自定义节点包 + Manager | 约等于我们的 pack，但 v1 不开放第三方安装 | **不做**，pack 由平台维护 |
| 分组框（group）、Reroute、PrimitiveNode、子图 / 组节点 | 画布整理与复用 | **不做**（v1 用模板复用代替子图） |
| 双击节点标题重命名、节点配色 | 小成本、高频 | **做**，重命名必须（模板里节点名要能看懂） |
| 种子 / control_after_generate | 对应「每次运行随机 vs 固定」 | **不做**，v1 由执行器决定 |

核心借鉴只有一句：**ComfyUI 的模板也从不「绑定」，用户打开模板就是复制了一份自己的。** 这与第 2 节的结论一致。

## 7. 数据模型

```text
wf_templates         id, pack_id, line, name, summary, status(draft|published|archived),
                     source_product_id, source_graph_id, copied_count, revision,
                     created_at, updated_at, deleted_at
wf_template_versions id, template_id, revision, graph_json, note, created_at   -- 不可变
wf_graphs（现有表加列） product_id, forked_from_template_id, forked_from_revision
                     -- 现有 (id, name, line, graph_json, revision, created_at, updated_at, deleted_at)
```

删掉的：`wf_bindings`（上一版提的），**不做**。它把模板当真相源，正是冲突的来源。

### 不变量

1. 模板版本不可变，改模板只能新增 revision。
2. 产品图 `product_id` 非空；`forked_from_*` 只用于追溯，不产生运行时依赖。
3. 运行开始时编译成冻结定义并记 `source_graph_revision`（内核 `workflow_run_definitions` 已有 `integrity_hash`），此后改图不影响该运行。
4. 模板被复制时 `copied_count + 1`，仅作统计，不影响任何数据。

## 8. 谁在做这些事（角色）

一人多职场景下，两个入口是**同一个人的两种状态**，不是两个角色：

- 「我这个产品要干活了」→ 产品流程页。
- 「这套跑通了，下个产品能省事」→ 保存为模板。
- 「下个产品开始了」→ 从模板复制 → 改 → 跑。

所以研发入口不需要权限体系，也不需要审批流。模板库是记事本，不是审批系统。

## 9. v1 范围

**做**：模板库列表 + 从模板复制 + 空白新建 + 保存为模板（含脱敏对话框）+ 产品流程页三栏进度 + 只读画布视图 + 编辑跳转 + 待确认进行动清单。

**不做**：模板市场 / 分享链接 / 平台级审批 / 跨产品合并 UI（只显示差异数量）/ 第三方 pack 安装 / 子图。

## 10. 验收

| # | 场景 | 期望 |
| --- | --- | --- |
| E-V1-1 | 研发 → 工作流模板 → 从「游戏 v1」复制到产品 A | 生成产品 A 的图，`forked_from_template` 指向模板；模板 `copied_count` +1 |
| E-V1-2 | 在产品 A 流程页改提示词并保存 | 只影响 A；模板内容不变 |
| E-V1-3 | 产品 A 跑通后「保存为模板」 | 弹出脱敏清单，`input.brief` 文本被清空，提示词保留；模板库出现新模板 |
| E-V1-4 | 产品 B 从 A 的模板复制并运行 | B 的图没有 A 的需求原文与导出路径 |
| E-V1-5 | 模板新增 2 个节点，产品 A「对比上游」 | 显示「上游新增 2 个节点」，A 的图不变 |
| E-V1-6 | 产品 A 没有图时进入流程页 | 显示「从模板开始」而不是空画布 |
| E-V1-7 | 运行跑到人工节点 | 行动清单顶部出现「待我确认 1 项」，点进去到该运行 |
