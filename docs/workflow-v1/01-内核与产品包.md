# 工作流 v1 · 01 内核与产品包

状态：待确认。回答一个问题：**哪些东西是内核、哪些是某条产线自己的，边界怎么保证。**

## 1. 分层与依赖方向

```text
src/shared/workflow-*.ts      内核：端口 / 图 / 校验 / 预演（纯函数，零 IO）
        ↑
src/packs/<line>/index.ts     产品包：只声明节点、模板、产物类型、校验器引用
        ↑
src/host/workflow-*.ts        宿主：存储、路由、把图编译成运行定义、调用 kernel
        ↑
src/client/workflow/*.tsx     界面：画布、属性面板、预演结果
```

依赖只能向上，不能向下，也不能横向：

| 层 | 可以 import | 禁止 import |
| --- | --- | --- |
| shared 内核 | 无（只 Node 内置纯函数） | host / client / packs / workflow 内核实现 |
| packs | `src/shared/workflow-canvas-model.ts` | host / client / `src/workflow/*` |
| host | shared、packs、`src/workflow/*`、DSH 宿主 | client |
| client | shared 的类型与纯函数 | host / `src/workflow/*` / Node API |

## 2. 内核负责什么（不可下放）

1. 端口类型注册表（8 种，见 [02](02-画布与节点规范.md)）
2. 图模型与不变量：`version / name / line / nodes / edges`、上限、ID 规则
3. 连线规则：类型匹配、一入一线、禁自连
4. 拓扑排序与结构校验（环、缺输入、产物无下游）
5. 预演（plan）：拓扑序、执行者分类、Markdown 文本
6. 存储与版本：`wf_graphs`、revision 乐观锁、软删除
7. 图 → 运行定义编译（v1 新增，M1）
8. 执行：复用 `src/workflow/m1-kernel.mjs` 的运行 / 步骤 / 尝试 / 快照 / 采用 / stale / 恢复
9. HTTP 路由骨架与 `/catalog` 聚合
10. 画布界面骨架：节点库、画布、属性面板、预演面板

## 3. 产品包负责什么

只有声明，没有执行逻辑：

```ts
export interface ProductPack {
  id: string                  // 'game' | 'novel' | 'drama' | 'sample'
  version: string             // semver，创建运行时冻结
  label: string               // '游戏'
  summary: string             // 一句话说明
  accent: string              // 主题色
  nodeDefs: NodeDef[]         // 节点定义（端口、配置 schema、执行者、提示词引用）
  templates: PackTemplate[]   // 预置画布
  artifactKinds: ArtifactKind[]   // 领域产物类型（game-brief / game-rules …）
  validators: ValidatorRef[]      // 机器校验器的名字与输入类型（实现按阶段注册）
  executors: ExecutorRef[]        // 节点怎么跑：dsh-session / tool-service / human / unavailable
  capabilities?: string[]         // 需要的宿主能力，如 'game-studio'
}
```

注册规则（M0 实现）：

- `id` 唯一；节点 `type` 必须以 `<packId>.` 开头，或属于内核通用前缀（`input.` / `retrieve.` / `flow.` / `output.` / `check.` / `human.`）。
- 节点只能使用内核已注册的端口类型；需要新类型时先升内核，不允许包私自定义。
- 模板注册时必须过 `validateGraph` 且无 error。
- 包与包之间不得互相引用；共享能力只能上提到内核。

## 4. 解耦红线（五条）

| # | 红线 | 违反后果 | 检查方式 |
| --- | --- | --- | --- |
| L1 | 内核文件不得出现产品线业务词（游戏 / 小说 / 短剧 / game / novel / drama 作为业务含义） | 加一条线就要改内核 | 禁词扫描 + 人工复核豁免注释 |
| L2 | pack 不得 import host / client / `src/workflow/*` | 包能偷偷写库、发请求 | import 图静态检查 |
| L3 | pack 不得直接读写文件、数据库、HTTP | 声明与执行混在一起 | 同上（禁 node:fs / node:http / sqlite） |
| L4 | 跨线共享的东西先升内核 | 三条线各写一套 | 评审 + 目录检查 |
| L5 | 界面不得写死产品线列表与节点目录 | 加线要改前端 | tab 必须来自 `GET /catalog` |

对应脚本：`scripts/verify-workflow-boundaries.mjs`（M0 交付）做四件事：

1. 扫描内核文件（`src/shared/workflow-*.ts`、`src/host/workflow-*.ts`、`src/client/workflow/*`）的禁词，输出命中清单。
2. 解析 pack 的 import，违反 L2 / L3 直接 fail。
3. 调 `buildCatalog()`，断言每条线、每个节点都来自某个已注册 pack，且节点 id 前缀匹配。
4. 断言「挂示例包前后，内核文件内容 hash 不变」。

## 5. 现有耦合点清单（实测）

| 位置 | 现状 | 改成 | 影响面 |
| --- | --- | --- | --- |
| `src/shared/workflow-canvas-model.ts:13` | `export type ProductLineId = 'game' | 'novel' | 'drama'` | 改成 `type ProductLineId = string`，线清单改由 pack 注册表提供 | 全仓引用点约 20 处，改类型别名即可 |
| 同文件 `:110` `NODE_DEFS` | 27 个节点（通用 9 + 游戏 6 + 小说 6 + 短剧 6）挤在一个数组 | 通用 9 留内核；其余搬 `src/packs/game/nodes.ts`、`novel/`、`drama/` | 节点定义搬文件，引用改 `registry.defById` |
| 同文件 `:900` `TEMPLATES` | 三条线模板写在内核 | 搬进各自 pack 的 `templates.ts` | 模板查询改走注册表 |
| 同文件 `:96` `PRODUCT_LINES` | 内核写死三条线 | 由注册表构建 | `lineOf()` 改查注册表 |
| `src/host/workflow-canvas-store.ts:32` | 表只有 `line` 列 | 增加 `pack_id`、`pack_version` 列（带默认值迁移） | 迁移脚本 + 向后兼容读旧行 |
| `src/client/workflow/canvas-panel.tsx` | 顶部 tab 遍历 `PRODUCT_LINES` | 遍历 `catalog.lines` | 前端只吃接口 |

这六处是「三条线耦合在一起」的全部实质来源。改完之后，加一条新产线 = 新增一个目录 + 注册表加一行，内核不动。

## 6. 复用怎么证明（不靠嘴）

交付 `src/packs/sample-line/`：1 个节点（`sample.outline`，`markdown → json`）、1 个模板、0 个执行器、1 条最简产物类型。要求：

- 挂上后 `GET /workbench-api/workflow/catalog` 多一条线；
- 画布能画出这个节点、能连线、能预演；
- 该线节点在 M1 之后可以标「无执行器」而不是让内核崩；
- 内核文件 `git diff` 为空。

这条包只用于验收，不进产品界面（用一个开关关掉）。

小说 / 短剧以后怎么挂（只写映射，v1 不实现）：

| 小说节点 | 复用内核的什么 |
| --- | --- |
| `novel.bible` 设定集 | `generate` 类 + `human.review` |
| `novel.outline` 大纲 | 同上，产物类型 `novel-outline` |
| `novel.chapter` 章节 | 长文本生成 + 章节级快照 |
| `novel.style-check` | `check.rules` 加一个 `validatorRef` |
| `novel.export` | `output.publish` 换导出器 |

短剧同理（分集 / 场次只是产物 schema 不同）。这也是「不要耦合」的真正含义：**差异在 schema，不在调度。**

## 7. 版本与兼容

- 每条线有 `version`；画布保存时记录 `packId + packVersion`。
- 运行创建时冻结版本；之后包升级不改历史运行，只在新建时用新版本。
- 节点类型在包里改名 = 破坏性变更：旧画布加载时该节点被 `normalizeGraph` 记为 `node_unknown` 并丢弃（已有行为），同时在界面提示「有节点因包升级失效」，不静默吞掉连线。
- 包的删除不删用户画布；加载时标「包缺失，只读」。
