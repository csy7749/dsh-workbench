# 工作流 v1 · 02 画布与节点规范

状态：实施中。本文保留早期画布契约；2026-11-17 的画布与 DAG 顺序、实际进度和未验收项以 [07](07-画布产品化补充计划.md) 为准。当前还包括模型、角色与执行配置端口；端口可见不代表对应运行语义已经实现。

## 1. 端口类型（8 种，内核拥有）

| 类型 | 含义 | 典型内容 | 颜色 | 谁产生 |
| --- | --- | --- | --- | --- |
| `text` | 纯文本 | 一段话、提示词 | `#60a5fa` | 输入、生成 |
| `markdown` | 结构化文档 | 简报、设计文档、章节 | `#a78bfa` | 生成、人工 |
| `json` | 结构化数据 | 规则、参数表、清单 | `#22d3ee` | 生成、工具 |
| `table` | 表格 | 数值表、关卡表 | `#fbbf24` | 工具、生成 |
| `report` | 检查报告 | 校验结果、诊断 | `#f472b6` | 校验节点 |
| `file-set` | 文件集 | 工程目录、导出包 | `#34d399` | 工具、导出 |
| `any` | 任意 | 汇聚、透传 | `#94a3b8` | — |
| `control` | 控制信号 | 分支开关、终止 | `#eab308` | 校验节点的 fail 出口 |

规则：`any` 双向通配；其余必须同类型。8 种之外的端口类型不允许产品包私自定义（L4）。

## 2. 节点契约

已实现字段（`src/shared/workflow-canvas-model.ts:39-50`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | 是 | 全局唯一，`<pack>.<name>` 形式 |
| `title` | string | 是 | 中文名 |
| `cat` | NodeCategory | 是 | input / retrieve / design / generate / tool / human / check / output |
| `actor` | Actor | 是 | agent / human / auto（预演里统计人工步） |
| `hint` | string | 是 | 一句话说明，显示在节点库 |
| `lines` | ProductLineId? | 否 | 省略 = 全线通用 |
| `inputs` | PortSpec[] | 是 | `{id,label,type,optional?}` |
| `outputs` | PortSpec[] | 是 | 同上；校验节点可有 pass / fail 双出口 |
| `config` | ConfigField[] | 是 | `{key,label,kind,value,options?,min?,max?,step?,hint?}` |

M1 起新增字段（执行期需要，画布期可缺省）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `executor` | `'dsh-session' \| 'tool-service' \| 'human' \| 'unavailable'` | 谁来跑；`unavailable` 时界面按钮禁用并给出原因 |
| `capability` | string? | 需要的能力，如 `game-studio`；缺失时节点只读 |
| `artifactKind` | string? | 产物领域类型，如 `game-rules` |
| `promptRef` | string? | 提示词模板 ID（不把整段提示词写进图里） |
| `requiredChecks` | string[] | 系统采用前必须通过的机器校验名 |
| `adopt` | `'system' \| 'human'` | 由节点是否 human 推导，不单独配置 |

配置项（`ConfigKind`）：`select`（需 options）、`number`（min / max / step）、`range`、`text`、`textarea`、`check`。未知键在 `coerceConfig` 里被丢弃，数值夹到区间，不报错（`src/shared/workflow-canvas-model.ts:484`）。

## 3. 连线规则

| # | 规则 | 拒绝 code |
| --- | --- | --- |
| 1 | 不能连自己 | `self_link` |
| 2 | 两端节点必须存在 | `node_missing` |
| 3 | 端口必须存在 | `port_missing` |
| 4 | 类型匹配（`any` 通配） | `type_mismatch` |
| 5 | 一个输入端口只收一条线 | `input_taken` |

第 5 条的唯一出口是 `flow.join` 这类显式多入节点（其 2、3 路端口标 `optional`），不是允许多条线打同一个口。汇合策略配置为「全部命中」时，任意一个接线分支未命中都会跳过汇合；配置为「任一命中」时，会等待所有接线分支结束，只绑定有效产物，并在冻结输入记录中保留未命中分支的快照或跳过事件来源。任一命中仍没有有效输入时，同样跳过汇合。

## 4. 图 JSON 规范

```json
{
  "version": 1,
  "name": "游戏：一页简报到规则",
  "line": "game",
  "nodes": [
    { "id": "brief-1", "type": "input.brief", "x": 120, "y": 160, "config": { "text": "做一个 30 秒内能上手的塔防", "mustExist": true } },
    { "id": "gdd-1", "type": "game.gdd", "x": 420, "y": 160, "config": { "tone": "简洁" } }
  ],
  "edges": [
    { "from": { "node": "brief-1", "port": "out" }, "to": { "node": "gdd-1", "port": "brief" } }
  ]
}
```

上限（`GRAPH_LIMITS`，`src/shared/workflow-canvas-model.ts:457`）：节点 200、连线 400、序列化后 512 KB。宿主再挡一次字节数。

**污染数据策略**：`normalizeGraph` 一律「丢弃 + 记 warn」，绝不静默改坏（`src/shared/workflow-canvas-model.ts:520`）：

| code | 级别 | 含义 |
| --- | --- | --- |
| `nodes_missing` | warn | 没有 nodes 数组，按空图 |
| `node_unknown` | warn | 未知节点类型，丢弃 |
| `node_line_mismatch` | warn | 节点不属于当前产品线，丢弃 |
| `node_id_fixed` | warn | id 非法或重复，已改名 |
| `nodes_truncated` / `edges_truncated` | warn | 超上限，多余丢弃 |
| `edge_dangling` | warn | 连线一端节点不存在，丢弃 |
| `edge_port` | warn | 端口不存在，丢弃 |
| `edge_type` | warn | 类型不匹配，丢弃 |
| `edge_dup` | warn | 输入端口已被占用，丢弃 |

## 5. 结构校验（`validateGraph`，随时可全量跑，不调模型不读盘）

| code | 级别 | 含义 | 用户该做什么 |
| --- | --- | --- | --- |
| `empty` | error | 画布是空的 | 拖一个输入节点 |
| `cycle` | error | 有环 | 删掉回边 |
| `input_missing` | error | 必填输入没接线 | 接线或用 `flow.join` |
| `brief_empty` | error | 需求节点标了「必须填写」但为空 | 填内容 |
| `no_downstream` | warn | 有产物但没下游 | 接下游或删节点 |
| `dead_end` | warn | 没有输入的空执行 | 补输入 |
| `config_empty` | warn | 关键文本配置为空 | 填配置 |
| `no_output` | warn | 没有任何输出节点 | 加一个 `output.*` |

## 6. 预演（plan）

`planOf(graph)` 输出：`{ ok, line, name, steps[], counts{total,agent,human,auto}, issues[], markdown }`。语义：

- 步骤顺序 = 拓扑序；同层按画布节点数组顺序（稳定，不随机）。
- `counts.human` 统计 `actor==='human'` 的节点数——用户看到「这条线要停几次」。
- 只有 `ok=true` 才允许「开始运行」；`ok=false` 时按钮禁用并列出 error。
- 预演**不执行、不写盘、不调模型**；它只是「这张图跑起来会是什么样」的文字说明。

## 7. 存储契约（已实现）

表 `wf_graphs`（`src/host/workflow-canvas-store.ts`）：`id / name / line / graph_json / revision / created_at / updated_at / deleted_at`，另存产品归属、模板来源与 pack 版本；索引 `idx_wf_graphs_updated(deleted_at, updated_at DESC)`。

- 保存带 `baseRevision`；不匹配返回 `{ok:false, conflict:true}` → HTTP 409，不覆盖别人。
- 软删除，`deleted_at` 非空即不可见。
- M0 增列 `pack_id`、`pack_version`（默认 `'game'` / `'1'`，旧行兼容）。

## 9. 变更规则

1. 加端口类型、改连线规则、改 `GRAPH_LIMITS`：属于内核变更，必须同步改本文与 `scripts/verify-workflow-*` 断言。
2. 加节点：属于产品包变更，不改内核；节点 id 加在包内，`version` 升 minor。
3. 改已有节点端口：破坏性变更，旧画布对应连线会被丢弃并记 `edge_port`，界面必须提示而不是静默。
4. 图 JSON 只在 `version` 升级时改结构；v1 内不加字段就加字段，加可选字段按向后兼容处理。
