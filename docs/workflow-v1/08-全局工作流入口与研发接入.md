# 工作流 v1 · 08 全局工作流入口与研发接入

状态：第一阶段已接入源码并完成下列自动化 / 隔离浏览器检查，真实 DSH 桌面待验收。用户于 2026-11-19 确认产品定位与实施顺序；后续研发模块接入仍待实施。

## 已确认的产品定位

工作流是跨项目、跨研发模块的共用能力。「工作流」入口放在工作台内部侧栏，工作台首页提供运行摘要；产品设计、UI 设计、DEMO、测试和 Bug 页面继续管理领域内容，并逐步接入共用的工作流执行体系。本文「全局」指跨项目汇总范围，不代表最外层导航层级。

2026-11-19 位置修正：用户确认工作台内部的安排即可，不要在最外层增加与「工作台」同级的「工作流」按钮。移除该外层按钮及状态标记，保留内部侧栏、门户摘要和准确运行详情。

单项编辑和临时协作可直接操作；存在前后依赖、审核、重复交付或失败恢复的多阶段任务适合工作流。同一件事从领域页面或工作流启动，都应关联同一次领域执行与结果，不重复派发，不维护两份互相冲突的状态。流程默认按具体产品归属，跨项目入口只做汇总，不改变既有作用域。

## 第一阶段：运行可见与准确进入

- 工作台内部侧栏提供「工作流」常驻入口及待处理数量，进入跨项目运行汇总；门户摘要显示运行中、待处理数量，点击运行可直达本次详情。
- 工作流首页默认展示活跃运行与待处理，提供全部项目 / 当前项目筛选和近期历史。模板入口与运行分开，复用现有工作流模板页面。
- 工作台门户在项目列表上方显示「工作流动态」，默认跨项目，展示有限条摘要，并可查看全部。
- 摘要包含项目 / 产品、流程、本次运行、状态、当前节点、已完成 / 总步骤、跳过数及最近更新时间。等待人工、异常阻塞优先；手动暂停与异常区分；不估算剩余时间。
- 快捷进入准确定位本次 runId，展示冻结运行及对应节点，不能落到同图最新运行或其它产品。原图被修改、删除时，已有运行仍可查看；保留已有人工确认、会话、产物与运行控制。
- 使用同一个轻量只读摘要源，后台共享刷新；离开画布后仍更新。读取失败保留上次数据并提示状态暂不可更新，不伪装为零运行。刷新不覆盖编辑器、焦点或未保存内容。
- 第一阶段仅汇总已有画布运行。产品设计团队派发、UI 生成、测试运行尚未接入时，不把它们伪装成已接入工作流。

## 后续阶段：研发模块逐步接入

1. 产品设计：优先迁移已有「业务模块设计文档 → 提炼模块 → 产品设计文档 → 交叉检查」四阶段串行流水线，明确输入版本、产物回写、审核和恢复。
2. UI / DEMO：产品设计 → 页面规划与设计规范 → 审核 → DEMO；领域页面展示关联运行与产物，保留独立编辑入口。
3. 测试 / Bug：测试设计 → 用例 → 执行 → 录 Bug → 修复 → 回归。复用既有测试运行及 Bug 身份，实际执行、人工验证和未评估必须区分；不能用模型结论代替通过证据。

后续接入应逐项确认执行契约、取消/恢复、权限、输入与产物版本及幂等性，再实现和验收。本轮先完成第一阶段，不将后续规划标记为实现。

2026-11-26 独立图片扩展：已建立 [产品图片长期优化计划与 IMG 台账](../product-images-roadmap.md)。图片页先完善领域操作，未来接入工作流时复用同一次图片操作与结果，Pack 只声明能力，由宿主服务执行；产品选择、工作流采用与下游实际使用分别验收。该专题不改变上述研发接入顺序，不增加本篇第一阶段或原 v1 的完成门槛，图片节点目前仍属后续规划。

## 第一阶段验收

- 不进入具体产品，在工作台内能看到跨项目运行及待处理；门户摘要与内部侧栏待处理数量一致；最外层没有新增的同级「工作流」按钮。
- 两个产品共用一个工作区、同图多次运行、旧运行晚于新运行等待审核，均准确进入点击的那次运行。
- 运行原图修改或删除、产品被删除时仍能查看冻结运行；缺失工作区时明确限制创建会话，不回落到其它项目。
- 等人工、异常暂停、手动暂停、完成、取消、分支跳过、上游重跑后的过期步骤，摘要分类与步骤计数正确。
- 网络/接口异常保留旧数据；恢复后更新；隐藏/恢复页面和卸载不产生并发刷新或定时器泄漏。
- 不改动现有产品设计、UI、DEMO、测试执行和人工确认契约；不为了观察运行而创建真实模型会话。
- 使用隔离库及合成内容做宿主/客户端自动化检查；真实 DSH 入口、主题、布局、导航和会话跳转另行记录。
