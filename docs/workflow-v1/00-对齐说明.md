状态：实施中（2026-11-15，Asia/Shanghai）。用户已确认完整 v1 范围、审核修订规则与项目内独立产品归属；本轮补充的执行配置节点约定见下节。历史 D 项中的技术实现选项按本计划推进，不重复要求逐项批准。

**2026-11-17 更新**：用户反馈当前产品中尚未看到可用的画布与节点，要求先做成熟的 DAG 画布与流程，之后再集中验收数据、模型与 Bug。以 [07 画布产品化补充计划](07-画布产品化补充计划.md) 为当前画布需求、进度和验收口径；下文有关线性范围、待确认项和“已实现”的旧描述均为历史记录，不代表当前承诺或桌面验收通过。产品流程改为画布优先，多分支基础实现不等于成熟 DAG 已完成。

## 本轮确认：执行配置作为画布节点

- 模型、角色分别提供配置节点，经配置组合节点输出给 AI 业务节点；同一配置可连接多个业务节点。未连接时继承流程默认配置。
- 本次实际接通模型与完整角色正文；Skill、MCP 配置后续扩展，不作为本次交付项，也不显示为已接通。
- 配置边与业务数据边分开；配置节点不占执行步骤，编译时解析并冻结配置。运行记录区分请求配置与实际生效配置，不静默换模型。
- 机器硬校验失败停在出错节点，允许修订或重试；规则编辑后重新校验，设计稿修改使规则及后续过期，重新生成后再确认。语义检查仅提示，不代表玩法已验证。
- 流程归项目内独立产品，不能用项目目录冒充产品 ID。首条验收使用独立演示产品，不修改 Unity 工程。
- 本次完成画布、模板复制与保存、真实生成、线性推进、人工审核、历史与过期标记、文件导出。Unity 构建/试玩、生图、小说短剧真实执行、任务视图联动继续暂缓。

## 1. 为什么重起一份文档

旧 `docs/workflow-plan/` 19 篇、2614 行，是全景规划，覆盖 W0–W6、游戏 P1.5、聊天工作室、素材、研习多条工作线。实际执行时错了两步：

1. **顺序错**：先花两天做 M0-B「崩溃恢复 + 可信身份」验收，再回头想「一条流程到底能不能跑通」。
2. **范围错**：一次铺了游戏 / 小说 / 短剧三条线 27 个节点，没有先让一条线从头跑到尾。

v1 只回答三件事：内核长什么样、游戏线交付什么、怎么证明小说 / 短剧以后能挂上而不改内核。

## 3. v1 范围

**做**

1. 画布：拖拽、连线、配置、缩放、保存、校验、预演（已实现，见第 7 节）
2. 图 → 运行定义编译：画布编译成 `m1-kernel` 的 definition（steps），**不新写执行引擎**
3. 单节点执行：选中节点点「运行」，经 DSH 会话产出候选快照
4. 线性连续执行：按拓扑序自动推进，遇人工节点停下等待
5. 人工确认：编辑草稿 → 确认 → 采用；驳回 → 回到同一待办
6. 快照与采用：原始输出 / 人工版本 / 采用记录分离，上游变化使下游 stale
7. 游戏线一条：一页简报 → 玩法规则 → 机器检查 → 人工确认 → 导出
8. 导出：把采用版本导出成本地文件集

**不做（v1 明确不承诺）**

- 多分支 / 循环 / 并行 / 子图 / 批处理
- 节点市场、第三方脚本节点、跨机器调度
- 小说、短剧的真实节点（只留一个约 20 行的示例包证明可插拔）
- 游戏构建、试玩、Unity 导入（本仓库没有 Game Studio 插件，无法实现）
- 生图 / 视频 / ComfyUI
- 聊天工作室、团队多员工编排

## 4. 已定（2026-11-15 对话拍板，不再讨论）

这五条是上一版设计的硬伤被指出后改定的，详见 [05 入口与归属](05-入口与归属.md)：

1. **工作流服务产品，不是产品服务模板。** 模板是起点，不是运行时依赖。
2. **复制即分离。** 产品图从模板复制那一刻就独立，模板涨版本碰不到已复制的产品；取消「绑定」概念（`wf_bindings` 不做）。
3. **图归产品。** 产品流程页里能直接编辑，「只读」的说法作废。
4. **产品图可保存为模板。** 显式动作 + 参数脱敏清单，把跑通的经验沉淀回模板库（学 ComfyUI）。
5. **双入口。** 研发组「工作流模板」（造起点 / 沉淀经验）+ 产品 tab「流程」（这个产品跑到哪）。

## 6. 完成定义（DoD）

全部满足才算 v1 完成：

1. 桌面端工作台里，不打开开发工具，能新建画布、拖 6 个节点、连线、保存，关掉重开还在。
2. 点「运行」让第一个节点真的产出内容（不是假数据），第二个节点能拿到它的输出。
3. 走到人工节点会停下；编辑后确认能继续；不确认就一直等待；重启后仍在等待。
4. 改上游并重新采用后，下游标 stale，不会把旧结果当新结果。
5. 游戏线模板能完整走到导出，产出文件在磁盘上能打开。
6. `scripts/verify-workflow-boundaries.mjs` 证明内核文件不含任何产品线字样；挂示例包不需要改内核文件。
7. 产品 A 能从「游戏 v1」模板复制出自己的图、改图不影响模板；跑通后「保存为模板」，复制到产品 B 时不含 A 的需求原文与导出路径（05 的 E-V1-2 / E-V1-4）。
