# 工作流 v1 · 03 游戏产线

状态：实施中。游戏线是首个样例，真实模型和桌面验收待 DAG 画布完成后集中进行；其它线只留示例包。当前安排见 [07](07-画布产品化补充计划.md)。

## 1. 目标与产物

v1 结束时，用户能用一条画布把「一句想法」变成**可执行的玩法规则**并导出成文件：

```text
一句需求 → 玩法设计稿（Markdown）→ 玩法规则（JSON）→ 机器校验（报告）→ 人工确认 → 导出文件集
```

| 产物类型 | 形态 | 落盘 | 用途 |
| --- | --- | --- | --- |
| `game-brief` | text | 快照 | 原始需求，不改写 |
| `game-gdd` | markdown | 快照 | 设计稿，人工可编辑 |
| `game-rules` | json | 快照 | 规则，后续构建节点的唯一输入 |
| `game-rule-report` | report | 快照 | 校验结果，不进下游 |
| `game-export` | file-set | 文件 | 导出给引擎 / 策划 |

## 2. v1 节点清单

| 节点 | 类别 | 执行者 | 输入 | 输出 | 机器校验 | v1 |
| --- | --- | --- | --- | --- | --- | --- |
| `input.brief` | input | human | — | `text` | 非空 | 已有 |
| `retrieve.knowledge` | retrieve | auto | `text` | `json` | 命中数 ≥ 1（可关） | 已有 |
| `game.gdd` | design | agent | `any` | `markdown` | 章节数、无占位符 | 已有 |
| `game.rules` | design | agent | `markdown` | `json` | schema 校验 | **新增** |
| `check.rules` | check | auto | `any` | `any` + `report` | 规则清单 | 已有 |
| `human.review` | human | human | `any` | `any` | 确认 revision | 已有 |
| `output.publish` | output | auto | `any` | — | 路径、覆盖策略 | 已有 |
| `game.balance` `game.level` `game.asset-spec` | design | agent | — | 表 / 文档 | — | 保留，v1 不进默认模板 |
| `game.build` | tool | unavailable | `json` | `file-set` | 构建产物清单 | **仅契约** |
| `game.playtest` | check | unavailable | `file-set` | `report` | — | **仅契约** |
| `game.unity-import` | tool | unavailable | `file-set` | `file-set` | — | **仅契约** |

`game.build` / `game.playtest` / `game.unity-import` 在 v1 里 `executor: 'unavailable'`、`capability: 'game-studio'`：画布上可见、可拖、可连线、能进预演（预演里标「需 Game Studio，当前不可用」），但运行时按钮禁用。**不允许假装接通。**

## 3. 默认模板：游戏 v1（6 节点 / 5 条线 / 停 1 次）

```text
[input.brief 需求]
        │ text
        ▼
[game.gdd 玩法设计稿] ──markdown──► [game.rules 玩法规则]
                                          │ json
                                          ▼
                                   [check.rules 机器校验]
                                     │ pass        │ fail
                                     ▼             ▼
                              [human.review]   （走 report，回到人工修规则）
                                     │ any
                                     ▼
                              [output.publish 导出]
```

- 只有 1 个人工节点：用户看到设计稿与规则，改完点「确认并继续」。
- `check.rules` 的 `fail` 出口在 v1 里**不允许自动回到上游**（无环），只把 report 呈现给人工节点旁边的诊断区；用户改完再确认。
- 模板里 `game.rules` 的提示词引用 `{{in}}`（上游 GDD 全文），不在这里内联整段提示词。

## 4. 节点契约细则

### 4.1 `game.rules`（新增）

- 输入：`in`（markdown，必填）
- 输出：`out`（json）
- 配置：`strictness`（select：宽松 / 标准 / 严格）、`maxGoals`（number，1–8，默认 3）、`includeOpenQuestions`（check，默认 true）
- 产物 schema：

```json
{
  "version": 1,
  "title": "环形卡牌 · 第一关",
  "player": { "count": 1, "controls": ["点击卡牌", "拖拽到槽位"] },
  "goal": ["在 3 回合内清空敌方阵型"],
  "fail": ["生命归零", "回合数用尽"],
  "loop": ["抽牌", "出牌", "结算", "补牌"],
  "acceptance": ["新玩家 30 秒内能完成第一次出牌", "第 1 关可通过"],
  "openQuestions": ["数值平衡？"]
}
```

- 机器校验（`requiredChecks`）：`schema`（必填字段齐全）、`non_empty`（goal / loop 非空）、`no_placeholder`（不含 `TODO` / `xxx` / `待定`）。
- 失败语义：schema 不合法 → 该尝试失败，保留候选供人工查看，不进入下游。

### 4.2 `check.rules`（复用）

v1 固定检查项：`schema`、`non_empty`、`no_placeholder`、`acceptance_resolvable`（每条验收能对应到 goal 或 loop 里的一个动作，用关键词匹配，命中不了记 `not_assessed` 而不是 fail）。

### 4.3 `human.review`（复用）

- 编辑器：Markdown（GDD）+ JSON（规则）双栏；规则用只读高亮 + 表单编辑两种模式。
- 主按钮固定文案「确认并继续」；另有「保存草稿」「确认并暂停」。
- 确认时写：草稿 revision、输入指纹、采用记录（actor=human）、事件；不确认则一直是等待。
- 驳回（request_changes）不清空草稿，回到同一待办。

### 4.4 `output.publish`（复用）

v1 只支持「文件导出」目标：写入 `<项目根>/workflow-out/<画布名>-<时间>/`，含 `brief.txt` / `gdd.md` / `rules.json` / `report.md` / `manifest.json`（含每份内容的 sha256 与来源快照 id）。

## 5. 人工节点的判定标准

用户看完要知道「改到什么程度算过」：

1. 设计稿必须写明核心循环四步与失败条件。
2. 规则 JSON 的 `acceptance` 至少一条，且是「可观察的行为」，不是「好玩」。
3. 有 `openQuestions` 时允许确认，但会写进导出包的 `manifest.json`，不静默丢。

## 7. 验收场景

| # | 场景 | 期望 |
| --- | --- | --- |
| G-V1-1 | 新建模板 → 填一句需求 → 单节点跑 `game.gdd` | 产出 Markdown，含 6 个章节；内容与需求相关（不是空模板） |
| G-V1-2 | 继续跑 `game.rules` → `check.rules` | 产出合法 JSON；校验报告 0 error；故意删掉 `goal` 时校验 fail 且下游不推进 |
| G-V1-3 | 到 `human.review` 改一句话 → 确认 → 导出 | 导出目录有 5 个文件；`manifest.json` 的 hash 与文件一致；运行状态为 completed |
| G-V1-4 | 确认前关掉桌面端并重启 | 仍停在同一个人工待办，草稿还在，不需要重跑上游 |
| G-V1-5 | 回到 `game.gdd` 改并重新采用 | `game.rules` 变 stale，界面提示「上游已变更」，旧导出不再标为最新 |

## 8. 与 Game Studio 的接口预留

只列接口名，不实现（避免以后改画布）：

- `capability: 'game-studio'`：版本、项目根、shelf 路径
- `submit / observe / collect / requestCancel / reconcile`：长任务五段协议（沿用 03 文档）
- 构建输入 = 冻结的 `game-rules` 快照 + 工程基准 hash；输出 = 文件清单 + hash
- 试玩报告字段：`level`（build-only / input-smoke / state-autoplay / deterministic-replay / human-played）+ `evidence[]`

## 9. v1 明确不做的游戏功能

- 数值表 / 关卡草案 / 素材规格自动生成（节点保留，不进默认模板）
- 工程回写（把规则写回游戏工程）——v1 只导出
- 多分支玩法比较、批量关卡生成
