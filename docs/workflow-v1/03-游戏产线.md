状态：原生 Host 的 14 工具、版本 / 素材 / 源码候选管理及自动集成验证通过；原 14 节点模板已带显式原创素材包完成真实创建、两轮试玩、构建、隔离预览及指定版本离线导出，节点和连线保留。另已实测本机 Blender 5.3.0 固定 worker 的原生 / GLB / PNG 与游戏组合。轻量设计导出模板继续保留；实际模型设计会话、DSH 桌面抽屉 / 画布与人工交付仍未验收，最终人工门未通过。当前画布安排见 [07](07-画布产品化补充计划.md)。

## 1. 目标与产物

轻量模板把「一句想法」变成**可执行的玩法规则**并导出成文件：

```text
一句需求 → 玩法设计稿（Markdown）→ 玩法规则（JSON）→ 机器校验（报告）→ 人工确认 → 导出文件集
```

完整产品模板把获批玩法变成可试玩的浏览器游戏，并以离线 HTML 与人工试玩记录完成交付闭环：

```text
需求 → GDD / 规则 → 人工批准 → 创建可玩工程 → 自动试玩 → 证据驱动修订
→ 最终构建 → 最终自动试玩 → 离线 HTML → 人工试玩验收
```

| 产物类型 | 形态 | 落盘 | 用途 |
| --- | --- | --- | --- |
| `game-brief` | text | 快照 | 原始需求，不改写 |
| `game-gdd` | markdown | 快照 | 设计稿，人工可编辑 |
| `game-rules` | json | 快照 | 规则，后续构建节点的唯一输入 |
| `game-rule-report` | report | 快照 | 校验结果，不进下游 |
| `game-export` | file-set | 文件 | 导出给引擎 / 策划 |

- 游戏：2D 竖屏收集躲避，单局 15 秒、3 颗心；计时结束获胜，生命归零失败，结算后可以重新开始。默认使用模板基线；批准规则可显式启用原创本地 SVG / WAV 包，不依赖生图服务。
- 画布：14 个节点、两个汇总节点；把工程信息和试玩证据共同传给修订与导出，同时测试分流汇合。设计批准与最终交付分别等待人工确认。
- 自动试玩：原型和最终版各 20 秒，按实际游戏参数运行；失败、重开及触屏没有被自动覆盖时，由人工补测。失败节点保留证据后暂停处理，不使用虚构通过结果继续运行。
- 隔离：使用绑定有效项目目录的独立测试产品；已有测试画布可保留节点与连线。原生 Host 在该目录下为本次创建尝试生成唯一的 `games/starlight-<后缀>`，不以旧提示中的目录名为任意写路径授权；不要把工作台源码仓库绑定成测试产品目录。
- 预览 / 导出：运行结果链接固定到实际 buildId；HTTP 预览使用受限 iframe 与 CSP，下载 / 导出读取同一已核验快照，不重新构建。工作副本变化不能冒充原来已试玩的版本。
- 范围：只支持 collector 固定玩法与批准的时长 / 生命参数；`game.playtest` 失败时最多尝试一轮恢复原创标准 `game.js`，保持批准规则、方向和素材，真实重测通过才采用；可设 `maxRepairs:0` 关闭。`game.revise` 核对干净证据并记录已采用的标准修复或无需修改原因。仍失败则停止，不是通用游戏引擎或 AI 自动改码。最终人工待办仍为未通过，必须真实试玩后填写确认。
- 批准合同：规则必须显式含 `nativeTemplate:"canvas-collector@1"`、整数 `durationSeconds`（3–60）及整数 `hearts`（1–9），否则在创建前暂停、不生成工程。旧的已批准规则缺字段时，保留同一画布，回到玩法审核，必要时重跑规则 / 审核节点，补齐并重新批准后再继续创建。新旧冻结运行的规则生成均有宿主范围补充提示，不需要手改旧外部工具提示。
- 素材包：只有批准规则显式含 `creativePack:"local-original-v1"` 才在创建时生成 / 采用两个 DrawAI 兼容 SVG 与两个 AnyAudio 兼容 WAV；缺省或 `none` 不开启。旧规则要先回同一审核补齐并重新批准，不靠工具提示暗中启用。Blender 不在默认素材包中，需独立工具或管理抽屉显式生成并采用。
- 证据回读：修订核对 / 最终导出会重新读取真实报告与 PNG，验证 `reportHash`、`screenshotHashes`、项目 / 构建身份，并通过 `buildCurrent` 确认源码与被测快照相同；仅有旧 JSON 摘要或已损坏 / 缺失的报告不能继续交付。
- 环境：试玩仅使用本机已有 Playwright / Playwright Core 与浏览器，缺失时明确报错，不安装包或下载浏览器。`offline:true` 是单文件封装标志；网络观察和真人设备试玩分别保留证据。
- 检查方法：`verify-workflow-game-test.mjs` 的模拟证据只说明编排；原模板 `--creative` 已实际跑四素材包、两轮真实浏览器至 won、错误 / 网络 0、指定版本下载 / 导出。另组合专项使用真实 Blender PNG，覆盖碰撞失败 / hit 音源启动和重开。全链设计输入仍是夹具，音频解码 / SourceStarted 不是人工听感，且不代表真实模型、DSH 桌面或人工交付已执行；本轮命令与分别对应的 report 见原生工坊方案第 14.6 节。

原运行卡片的“工坊管理 · 版本 / 素材 / 源码修订”抽屉可以读取当前 CAS、比较 / 恢复历史、生成 / 核验 / 试听素材、显式采用以及提交源码候选。候选生成不改变当前游戏；采用和恢复要求当前指纹并构建，完成后试玩为未评估，原 Attempt 证据仍固定在旧版本，须重新试玩并从相应节点重跑。源码候选一次真实核验，通过才采用，失败 / 取消回退，外部编辑冲突或未知进程须显式对账。抽屉的路由验证已覆盖，实际 DSH 真窗口操作仍在人工联合测试范围。

## 3. 轻量模板：游戏规则与导出（6 节点 / 5 条线 / 停 1 次）

```text
[input.brief 需求]
        │ text
        ▼
[game.gdd 玩法设计稿] ──markdown──► [game.rules 玩法规则]
                                          │ json
                                          ▼
                                   [check.rules 机器校验]
                                     │ pass        │ fail
                                     ▼             ▼
                              [human.review]   （走 report，回到人工修规则）
                                     │ any
                                     ▼
                              [output.publish 导出]
```

- 只有 1 个人工节点：用户看到设计稿与规则，改完点「确认并继续」。
- `check.rules` 的 `fail` 出口在 v1 里**不允许自动回到上游**（无环），只把 report 呈现给人工节点旁边的诊断区；用户改完再确认。
- 模板里 `game.rules` 的提示词引用 `{{in}}`（上游 GDD 全文），不在这里内联整段提示词。

## 4. 节点契约细则

### 4.1 `game.rules`（新增）

- 输入：`in`（markdown，必填）
- 输出：`out`（json）
- 配置：`strictness`（select：宽松 / 标准 / 严格）、`maxGoals`（number，1–8，默认 3）、`includeOpenQuestions`（check，默认 true）
- 产物 schema：

```json
{
  "version": 1,
  "title": "环形卡牌 · 第一关",
  "player": { "count": 1, "controls": ["点击卡牌", "拖拽到槽位"] },
  "goal": ["在 3 回合内清空敌方阵型"],
  "fail": ["生命归零", "回合数用尽"],
  "loop": ["抽牌", "出牌", "结算", "补牌"],
  "acceptance": ["新玩家 30 秒内能完成第一次出牌", "第 1 关可通过"],
  "openQuestions": ["数值平衡？"]
}
```

- 上面的卡牌示例仅演示通用设计文档 schema，当前原生 collector 不能执行该玩法。接入原生创建时，规则还必须包含以下顶层字段，并且 GDD / 规则确实符合 collector 的单人横移、下落星星计分、障碍扣血、生命归零失败、存活计时获胜及重开范围：

```json
{
  "nativeTemplate": "canvas-collector@1",
  "durationSeconds": 15,
  "hearts": 3
}
```

- 宿主给新建及旧冻结 `game.rules` 生成补充范围提示；不支持的玩法标记 `nativeTemplate:"unsupported"` 并写入 `openQuestions`。原生创建仅接受明确批准的 `canvas-collector@1` 和有效整数范围（时长 3–60 秒、生命 1–9），缺省 / 不支持时暂停，不回退到 15 秒 / 3 心创建。
- 可选顶层字段 `creativePack` 仅允许 `none` / `local-original-v1`；开启须进入规则批准快照。它选择受限原创本地四素材包，不代表批准任意媒体服务、Blender 执行或费用 / 网络操作。
- 机器校验（`requiredChecks`）：`schema`（必填字段齐全）、`non_empty`（goal / loop 非空）、`no_placeholder`（不含 `TODO` / `xxx` / `待定`）。
- 失败语义：schema 不合法 → 该尝试失败，保留候选供人工查看，不进入下游。

### 4.2 `check.rules`（复用）

v1 固定检查项：`schema`、`non_empty`、`no_placeholder`、`acceptance_resolvable`（每条验收能对应到 goal 或 loop 里的一个动作，用关键词匹配，命中不了记 `not_assessed` 而不是 fail）。

### 4.3 `human.review`（复用）

- 编辑器：Markdown（GDD）+ JSON（规则）双栏；规则用只读高亮 + 表单编辑两种模式。
- 主按钮固定文案「确认并继续」；另有「保存草稿」「确认并暂停」。
- 确认时写：草稿 revision、输入指纹、采用记录（actor=human）、事件；不确认则一直是等待。
- 驳回（request_changes）不清空草稿，回到同一待办。

### 4.4 `output.publish`（复用）

v1 只支持「文件导出」目标：写入 `<项目根>/workflow-out/<画布名>-<时间>/`，含 `brief.txt` / `gdd.md` / `rules.json` / `report.md` / `manifest.json`（含每份内容的 sha256 与来源快照 id）。

## 5. 人工节点的判定标准

用户看完要知道「改到什么程度算过」：

1. 设计稿必须写明核心循环四步与失败条件。
2. 规则 JSON 的 `acceptance` 至少一条，且是「可观察的行为」，不是「好玩」。
3. 有 `openQuestions` 时允许确认，但会写进导出包的 `manifest.json`，不静默丢。

## 6. 游戏构建、试玩与交付门槛

| 节点 | 输入 | 输出 | 依赖与缺失时行为 |
| --- | --- | --- | --- |
| 创建 | 获批设计包 | 在新 `games/<slug>` 下创建真实游戏项目 | 项目、标题、模板和首版构建 ID 必须来自工具结果 |
| 原型试玩 | 当前项目与构建 | 浏览器自动试玩 | 必须保存工具报告、终局和截图；失败不得进入修订为通过 |
| 修订与重建 | 原型试玩报告 | 标准修复 / 无需修改核对与真实构建 | 最多一轮固定标准源码恢复，真实重测通过才采用；自定义源码候选另走 CAS 试用 / 失败回退，不改变批准配置 |
| 最终试玩 | 最终构建 | 浏览器自动试玩 | 最终构建 ID 一致、终局为 won、错误与网络请求为 0、截图非空 |
| 离线导出 | 已通过试玩的最终构建 | 自包含 HTML | 项目与构建 ID 必须和最终试玩一致；不自动发布或分享 |
| 人工验收 | 最终 HTML 与自动证据 | 试玩记录 | tester、平台、时长、观察、已知问题、构建 ID 和 HTML 路径齐全；来源全部一致 |

自动试玩与人工试玩是不同证据。自动报告只代表工具实际运行结果；最终人工验收要求用户亲自打开同一 HTML 完成一局并记录过程。闭环只交付本地离线 HTML，不包含上线发布。

## 8. 原生提供方与原模板复测

当前执行五类节点操作与新增版本 / 素材 / 修订工具不要求安装 `dsh-game-studio`。历史 `game_studio_*` 为外部插件接口参考；工作台使用自己的 14 工具和宿主适配器：

- 创建 / 构建：`workbench_game_create/build` 返回真实 `projectId`、`buildId`、hash / bytes 与版本链接。Host 冻结产品、运行和尝试归属。
- 预览：`workbench_game_preview` 核对快照；运行卡片提供“打开游戏”“下载此版本 HTML”及独立沙箱 iframe。
- 试玩：`workbench_game_playtest` 只用本机已安装浏览器；保存真实终局、错误 / 网络计数、报告和 PNG，不代表人工验收。
- 离线交付：`workbench_game_export` 导出明确的已核验版本；工作流打包前还会回读报告 / PNG 指纹，不重建或发布。
- 版本：`history` / `restore` 读取、比较和 CAS 恢复；构建 / 试玩 / 备份分别默认 100 份及 256 / 256 / 128 MiB 配额，达限拒写，不自动删除历史。恢复与素材采用不沿用旧试玩为当前通过。
- 素材：DrawAI 仅原创单页基本形状 `.drawai` / SVG，AnyAudio 仅原创短过程音效原生工程 / PCM WAV；已实际通过本地上游解析、渲染 / 导出兼容。素材候选独立保存来源 / 许可 / hash，默认 128 份 / 256 MiB，禁外链与链接逃逸；这是受限格式桥，不运行完整插件 / 编辑器、SoundFont、TTS 或在线服务。
