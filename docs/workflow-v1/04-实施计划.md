# 工作流 v1 · 04 实施计划

状态：待确认。依赖 [00 对齐说明](00-对齐说明.md) 的 D1–D7 拍板结果。本文只排顺序与出口条件，不重复讲契约（契约见 01 / 02 / 03）。

## 0. 排期原则

1. **先证明一条流程能跑通，再证明它可靠。** 崩溃恢复、并发、fencing 这些 M0-B 已有代码，v1 不再投入验收。
2. **每个里程碑都有可执行出口**，跑不过就停在这一步，不进入下一条。
3. **不新增执行引擎。** 运行时一律走 `src/workflow/m1-kernel.mjs`；v1 只新增「图 → 定义」的编译层。
4. **每个里程碑结束都能在桌面端手操一遍**，不是只跑脚本。

估算按单人、熟悉本仓计；仅作排序参考，不作为承诺。

| 里程碑 | 内容 | 估算 |
| --- | --- | --- |
| M0 | 边界整改 + 示例包 + 真机验收画布 | 1 天 |
| M1 | 图 → 运行定义 + 单节点执行 + 路由 | 2 天 |
| M2 | 线性自动推进 + 人工确认 + stale | 2 天 |
| M3 | 导出 + 游戏线端到端 | 1 天 |

## M1 图 → 运行定义 + 单节点执行

**目的**：画布上的一个节点，点「运行」能真的产出内容，并落到内核的快照里。

### 任务

| # | 任务 | 文件 | 出口 |
| --- | --- | --- | --- |
| M1-1 | `compileGraph(graph): RunDefinition`：节点 → steps，边 → 依赖，节点 config → step 参数 | 新增 `src/host/workflow-compile.ts` | 6 节点模板编译出 6 个 steps，依赖关系与画布一致；有环直接抛错 |
| M1-2 | 节点契约扩展：`executor` / `capability` / `artifactKind` / `promptRef` / `requiredChecks` / `adopt` | `src/shared/workflow-canvas-model.ts` | 27 个定义补齐字段；`unavailable` 的节点在预演里标出来 |
| M1-3 | 建运行：`POST /workbench-api/workflow/graphs/:id/runs` 编译 + 调 `createRun` | `src/host/workflow-canvas.ts` | 返回 runId 与 step 列表 |
| M1-4 | 单节点执行：`POST /graphs/:id/runs/:runId/steps/:nodeId/run` | 同上 + 新增执行器适配 | `input.brief` 立即完成；`game.gdd` 通过 DSH 会话产出真实 Markdown |
| M1-5 | 执行器适配：`dsh-session`（走 DSH 派发）、`human`（建待办）、`unavailable`（直接报不可用） | 新增 `src/host/workflow-executors.ts` | 三类都能被调到，且失败有明确 error code |
| M1-6 | 产物快照：执行结果写成 snapshot，带 hash 与来源 | 复用 `m1-output-set.mjs` | 快照可读回，hash 与内容一致 |

### 出口条件

- 编译层单测：6 节点模板 → 6 steps；人工加环 → 报错；删掉一条边 → 依赖少一条。
- 真机：点 `input.brief` 运行 → 状态变完成；点 `game.gdd` 运行 → 面板里能看到生成的 Markdown 正文，且与需求相关。
- 失败路径：`capability: 'game-studio'` 的节点点运行 → 提示「需 Game Studio，当前不可用」，不产生假产物。

### 不做

- 不做自动推进（M2）、不做导出（M3）。

## M2 线性自动推进 + 人工确认 + stale

**目的**：点一次「运行全部」，流程自动按拓扑序往下走，到人工节点停住等人。

### 任务

| # | 任务 | 文件 | 出口 |
| --- | --- | --- | --- |
| M2-1 | 推进循环：单活跃节点，前一个 accepted 才 ready 下一个 | 新增 `src/host/workflow-runner.ts` | 模板从第一个节点跑到人工节点自动停 |
| M2-2 | 暂停 / 继续 / 取消：`POST /runs/:runId/{pause,resume,cancel}` | `src/host/workflow-canvas.ts` | 三个动作状态正确；取消后不能继续 |
| M2-3 | 人工待办：`GET /runs/:runId/steps/:nodeId/draft`、`PUT .../draft`、`POST .../confirm` | 复用 `m1-kernel` 的 human 映射 | 草稿可编辑保存；确认后采用并推进 |
| M2-4 | 人工界面：双栏编辑器 + 「确认并继续 / 保存草稿 / 确认并暂停」 | `src/client/workflow/canvas-panel.tsx` 新增运行侧栏 | 三个按钮行为与 03 文档一致 |
| M2-5 | stale 传递：上游重新采用 → 下游标 stale 并提示 | 复用 `m1-kernel` | 改 `game.gdd` 后 `game.rules` 显示「上游已变更」 |
| M2-6 | 运行状态在画布上可见：节点角标（待运行 / 运行中 / 等确认 / 已采用 / 过期 / 失败） | 客户端 | 一眼能看出卡在哪 |

### 出口条件

- 真机：模板一键跑 → 停在人工节点 → 改一句话 → 确认 → 继续跑到 `output.publish` 前。
- 重启桌面端：仍停在同一个人工待办，草稿内容还在，不需要重跑上游。
- 撤销确认（改上游）→ 下游 stale，旧快照不被当成新结果。

### 不做

- 不做并行、分支、循环、子图。

## 风险与预案

| 风险 | 概率 | 预案 |
| --- | --- | --- |
| DSH 会话派发慢 / 不稳定，`game.gdd` 经常超时 | 中 | 执行器加超时与重试上限（1 次）；超时即 failed，不自动重跑，保留候选供人工看 |
| 编译层与 `m1-kernel` 的 steps 语义对不上 | 中 | M1-1 先写纯函数单测对齐字段，再接路由；对不上就改编译层，不改内核 |
| 画布在真实窗口里样式错乱 | 中 | M0-9 真机验收前置；不行就回退到只用 `--dsh-` 变量的最小样式 |
| 拆 pack 时漏了引用导致 catalog 少节点 | 中 | M0-2 要求搬迁前后 catalog JSON 逐字段 diff |
| 用户对 D1–D7 有不同意见 | 高 | 每个 D 的代价已列在 00 文档，改动只影响对应里程碑，不推翻整体顺序 |
