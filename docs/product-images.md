# 产品图片素材与 dsh-image-gen 接入

日期：2026-11-27（Asia/Shanghai）。当前支持产品范围的静态图片生成／编辑、真实附件归档，以及本地静态图片导入、候选预览／比较、选用和原图下载。生成图与本地导入图进入同一个产品画廊。主入口是 **研发 → UI 设计 → 图片素材**，「产品设计」保留当前产品的快捷入口；无需先创建 UI 设计记录、游戏或工作流。

长期优化见 [产品图片素材路线与 IMG 台账](product-images-roadmap.md)，v2 operation／候选／来源格式见 [产品图片 v2 格式契约](product-images-v2-contract.md)。路线包括规格／风格、导入与比较、本地加工、批次／恢复及工作流消费。本文记录当前能力与已有验证；路线图中的未实施项不代表已经可用。

## 使用

1. 从侧栏「研发」打开「UI 设计」，在顶层「界面设计／图片素材」中切换到「图片素材」，选择项目和产品，并核对页面显示的关联工作区。产品需关联有效的本机工作区；也可从「产品设计」当前产品的「图片素材」快捷入口打开同一画廊。
2. 在同一个 DSH Host 启用并配置 `dsh-image-gen`。工作台使用插件保存的默认渠道与模型，凭据继续由插件管理；工作台不复制 Key、不自动安装插件、不测试付费出图。
3. 当前工具执行器需向宿主公开 `generate_image` 与 `edit_image` 原生入口。PTC 仅公开 `run_code` 时显示不兼容原因，工作台不修改全局执行器。
4. 输入主体、风格、用途及尺寸要求；编辑时明确选取本产品的一张候选作为参考。首次勾选额度确认后点击生成；当前产品与工作区的勾选或取消状态保存在本机，提交、修改描述、切换操作和重新打开页面都会保留，可随时手动取消。插件调用只执行图片工具，不额外发送 LLM 会话消息。
5. 成功后查看候选、来源渠道、模型、真实尺寸和 SHA-256。点击「采用图片」只记录产品素材选择；下载保留原图字节。后续具体使用位置由其他操作指定。

图片仍按产品 ID 与工作区归属，不属于某一份 UI 设计。两处入口使用同一图片服务和候选目录；切换入口不会迁移、复制素材或额外调用生成器。没有 UI 设计记录时也能使用图片页。

本地 PNG、JPEG 或 WebP 可从图片页导入为 v2 候选；导入只保存明确选取的文件内容，不扫描路径、不调用模型。可将 2–4 个候选加入并排比较，调整显示缩放并切换透明棋盘格。v2 候选还支持最多 50 个标签、备注和技术检查；检查分别报告 alpha 通道及真实透明像素，并明确标记视觉／文字判断尚未评估。预览由 Host 生成 WebP 派生图，在内存 LRU 中最多保留 64 项／32 MiB，单项最多 4 MiB；原图只用于显式下载或编辑引用。当前不提供裁剪、网格切图、规格卡或生成参数映射。

画廊与比较不按图片来源分开：支持「生成图与生成图」「导入图与导入图」「生成图与导入图」任意组合，最多同时 4 张。卡片和对比标题显示来源，以及生成工具实际返回的渠道／模型；未返回的身份不补造。点击各卡片的「加入比较／移出比较」即可调整，不重新生成或额外消耗模型额度。当前生成／编辑结果仍为 v1，本地导入为 v2；比较保留各自版本并读取对应预览。v2 导入候选暂不能作为现有生成器的编辑参考，此限制不影响混合比较。

首次联测可在独立测试产品中先生成两张图、再导入两张图，分别验证生成／生成、导入／导入、生成／导入和四图混合比较；随后刷新页面核对候选与比较选择，切换产品核对隔离。额度确认按产品与工作区记住选择，无需逐次勾选，每次生成仍需点击生成按钮；仅比较、刷新、恢复勾选或切换产品不能触发生成。本机存储不可用时，选择仅在当前视图中保留。真实渠道是否完成出图和账户费用状态须另行验收。

渠道及模型是否真正可用以实际调用结果为准。页面“可用”代表注册工具、附件读取和当前原生执行入口通过检查，不代表已测试凭据、账户额度或供应商连通性。

本机安装核查（2026-11-26）：Desktop profile 已声明且未禁用 `dsh-workbench` 1.13.0 与 `dsh-image-gen` 0.12.3，前者链接到本仓库。当时的使用指引为完成构建后重启 Desktop DSH，再进入已关联工作区的产品 → 图片素材；当前导航见上文「使用」。此记录证明安装配置；运行中的工具状态仍以页面检查为准。Web profile 未安装这两个插件。

## 结构与边界

```text
产品需求 → 宿主图片服务 → 已注册的 generate_image / edit_image
  → 结构化附件引用 → DSH 附件服务验证读取
  → 产品候选原图与 manifest → 预览／选用／下载
```

- `product-images-runtime.mjs` 通过正式 `ctx.tools.execute({ calls, signal, agent? })` 批量契约调用已有工具，校验 `result.value`；通过 `attachments.readImage` 捕获实际附件，不解析“已生成”之类自然语言，也不信任可选的 `savedTo` 路径。
- 编辑引用只能来自本产品已归档候选。需要会话工作区时，通过正式 Agent factory 创建绑定该工作区的空白 Agent，不提交 prompt／followup，完成后释放；不会借用随机活跃会话。只有身份与工作区均核对一致的原调用 Agent 才可复用。
- 原图与 manifest 保存在 `<产品工作区>/.dsh-workbench/product-images/<产品ID摘要>/candidates/<候选ID>/`；任务在同级 `jobs/`，选择清单单独保存在 `selection.json`。产品 ID、文件 hash、生成任务及参考关系相互绑定。
- 新导入图片与其 operation 保存在 `<产品工作区>/.dsh-workbench/product-images-v2/<产品ID摘要>/`，v2 元数据、检查报告和选择清单各自独立于 v1。请求的 `formatVersion` 缺省时按 v1 处理；客户端应明确传入 v2 候选版本。
- 只接收单帧 PNG／JPEG／WebP；实际解码校验，拒绝 GIF、APNG、SVG、类型伪报和损坏图片。单图最多 20 MiB／6400 万像素，每产品最多 200 个任务、512 MiB 候选。原图不做隐式缩放或压缩。
- 生成与编辑归入网络／额度能力；同时检查本地素材选择写入权限。读取和下载独立受工具策略约束。浏览器不能指定工作区路径、附件 ID、provider Key 或任意本地文件路径。
- 本阶段未新增工作流图片节点、无限画布、图库扫描、批量生成或游戏素材消费者。Cinderwatch 当前不采用外部图片槽；本页的“采用”不会改变游戏构建。
- 这是可选插件适配；不打包第三方插件源码，也不新增生成 Provider 的依赖实现。原有图片加工和素材工作流规划保留。

接口对照来源为本地 `dsh-image-gen` 0.12.3 源码，以及本机 DSH 0.2.3-alpha.2 安装包内工具、Agent、附件和系统提示词服务的公开契约。兼容性按运行时能力检查；未声称全部历史版本通用。Studio 浏览器路由不作为本阶段执行协议，其 ComfyUI 支持与聊天工具并不相同。

## 请求、失败和恢复

- 每次提交使用 UUID `requestId`。在调用生成器前独占创建并 flush/fsync 保存请求意图。同产品相同 ID、相同参数只返回原任务；参数不一致报冲突。刷新状态只发 GET，不重发生成。
- 单个 Host 进程内每产品最多一个未结束生成调用、总计两个。取消后原始调用尚未结束时继续保留并发限制；迟到结果不悄悄转为成功，也不自动归档。
- 已派发调用发生取消、超时、网络错误或归档不确定时保守记录 `unknown`。宿主重启后的遗留 `running` 也呈现未知；不自动重试。用户应先核对供应商记录及额度，再决定是否发起新请求。
- `unknown` 不证明远端取消成功；本阶段没有供应商任务查询、恢复和扣费对账协议。明确在派发前被拒绝、或已确定返回格式不可用的调用记录失败；失败同样不代表没有额度消耗。错误只保留稳定错误码，不保存供应商原始异常、URL 或凭据。
- 相同 ID 的文件独占创建提供持久防重；不同 ID 的并发限制是单个 Host 进程内的限制，不声明多进程互斥。
- 状态轮询只检查 manifest 和文件元数据；预览、选用、编辑引用时重新核验原图完整性。图库节点在候选变化时才重建，任务轮询不反复加载全部原图。

## HTTP 与 Agent 工具

HTTP 路由位于 `/workbench-api/product-images`：

| 路由 | 作用 |
| --- | --- |
| `GET /state?productId=…` | 插件／执行器状态、任务和候选 |
| `POST /generate` | `productId`、UUID `requestId`、`prompt`、`mode`、可选 `referenceId`、`confirmed: true` |
| `POST /import` | `productId`、UUID `requestId`、`fileName`、`mime`、base64 图片字节；仅接受静态 PNG／JPEG／WebP |
| `POST /select` | `productId`、`candidateId`、`formatVersion`（v1／v2）、布尔 `selected` |
| `POST /metadata` | v2 `productId`、`candidateId`、最多 50 个 `tags` 和 `notes` |
| `POST /check` | v2 `productId` 与 `candidateId`；将检查结果绑定到原图 hash |
| `GET /preview` | 返回不超过 1024 像素／边的 WebP 预览；派生物仅存于有界 Host 内存缓存 |
| `GET /image?productId=…&candidateId=…&formatVersion=…` | 经核验的原图；加 `download=1` 下载 |

生成请求同步等待本次工具；刷新页面后可通过状态接口观察已持久化任务。POST 校验同源、JSON 格式、字段白名单和请求大小。预览只返回允许的静态图片类型。

对应工具为 `workbench_image_list`、`workbench_image_generate`、`workbench_image_import`、`workbench_image_select`、`workbench_image_metadata`、`workbench_image_check`、`workbench_image_export`。生成工具使用 `mode=edit` 与明确 `referenceId` 编辑；用户必须明确要求本次生成后才能传 `confirmed: true`。导入、标签、检查、选择和下载都不调用模型。这些工具独立于游戏节点及工作流运行。
