## 3. 源码静态发现与复验入口

这些是本轮读到的具体实现及推断，尚未用模型或业务脚本复现。先写脱敏探针确定影响和最小修复，不能将文档修正当成代码修复。

| 源码入口 | 已见实现 | 需要验证什么 |
| --- | --- | --- |
| `src/host/agent-model.ts` 的 `buildTeamKickoff` | 交付方式只特殊处理 ui.design、demo.build，其余落到 `workbench_idea_expand` | product.design 的目标提示词与通用交付指令冲突；新执行器必须使用正确候选交付工具，不能直接沿用该分支 |
| `src/host/index.ts` 的 `registerProductTools`，`src/client/app.ts` 的 `pipelinePrompt` | 提示词传 kind，tool schema 不声明 kind 且 additionalProperties=false | 参数是否被拒绝 / 丢弃、保存的实际 kind；调用层与保存层分别验证 |
| `saveNote`、`publishProductNote`、audit 提示词 | 无 moduleId 的 product_design 推导相同 pd 键；module_design 缺 moduleId 时不自动得 md 键；publishProductNote 未透传显式 docKey | 正文 / 报告隔离，先文档后模块时稳定身份，多导图与多文档重跑不丢失 / 重复 |
| `saveNote` | 正文 slice 到 500000 字符；文件镜像失败仅记日志；旧笔记版本采用有限保留 | 新发布边界预检容量并校验结果，不把镜像失败或截断视为完整成功；旧笔记版本不替代不可变工作流快照 |
| `listDesignDocs` | 聚合查询未过滤 archived_at，只分 module_design / product_design / feature_design 三桶 | 普通列表归档测试不覆盖该聚合；试点输入不能混入已归档文档 |
| `src/host/sync.ts` 的 notes 分支 | 同步调用 saveNote 并回写 updated_at；未透传全部设计归属字段 | 同步或旧 UI 修改是否清除 kind / docKey 等元数据；发布基准检查须发现字段变化，同秒也有效 |
| `src/host/index.ts` 的 `apply` | 无 DatabaseSync 时启动 JsonStore | 工作流能力隔离、错误可见、旧工作台继续工作；不推断已支持工作流 JSON 降级 |

## 4. 仍需 M0 给出实测结论

- 目标 DSH profile 是否能强限制工具、区分人工操作身份、返回实际模型 / 角色 / Skill / 工具范围与输入交付证据。
- SQLite / 文件 / Draft 的故障恢复、Windows 跨卷和链接路径范围；断电持久性不能由普通进程退出测试推断。
- 新发布适配的领域 ID、报告键、字段 / hash 基准、镜像完成条件和原工具可隔离性。
- 租约、心跳、重试间隔、累计预算、单文件 / 总输出上限、去重记录保留期。
- M1/M2 各批次在上述细化后的实际工作量；不复用缺少这些边界的旧估算。

这些事项沿用 11 的原任务及 [12 的 Q19–Q21](workflow-plan/12-decisions-risks.md) 跟踪；本报告不维护第二套待办复选框。当前改动只让实施依据更一致，尚不构成 M0 通过。
