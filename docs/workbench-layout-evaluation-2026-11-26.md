# 工作台实机布局评估

日期：2026-11-26（Asia/Shanghai）

对象：当前运行中的 DeepSeek Harness 工作台；窗口约 1920 × 1032。

目的：补充首页截图与静态代码检查，记录真实页面的信息层级和空间分配，为后续重设计定范围。本文件是评估，不是重构授权或实施记录。

## 结论

建议做**渐进式重设计和重构**，优先统一导航、项目上下文和页面骨架，再逐页迁移。工作台已经覆盖项目、产品设计、UI、DEMO、质量管理、任务与自动化工作流，不适合继续把新功能简单累加到首页或共用任务页面。当前关键问题是功能归属与信息排序不清，重复导航和页面头部挤压了设计与执行内容。

建议将产品组织成三个可辨认的工作域：我的工作、项目工作区、工作流运行；“资料”承载笔记、灵感和资产入口。进入项目后固定显示项目身份，并用概览、设计、执行、产物、质量组织项目能力。首页先展示待处理、继续中的工作、近期项目和产物，功能目录与配置后置。

保留现有项目/产品/运行/产物 ID、SQLite 数据、历史记录和工作流内核。先修复写入一致性与归属问题，再把新外壳逐页接入现有服务。不要因为换布局同时重写运行状态机、版本和人工确认契约。

### 外壳与密度

本次窗口同时显示 DSH 宿主侧栏和约 200px 的工作台侧栏，主区域约 1440px。工作台侧栏可收为窄图标轨，增加约 145px 主内容空间；这有用，但它也让项目和页面名称失去常驻可读性。更好的默认结构是保留易识别的工作域入口、减少重复列表，并允许二级导航按需收起。

页面密度也不是单一的“太挤”：导图与画布受到头部和两侧面板挤压；设计笔记顶部过密、卡片过松；首页和总览则是低优先级内容过多。重设计应按内容类型制定密度：运行清单紧凑、长文档舒适阅读、图形画布优先、项目概览以行动和状态为主。

## 重设计优先级

1. **项目归属与导航。** 先定义全局与项目范围；UI/DEMO 不应回落到任务导航；创建、生成、发布必须携带明确项目身份。清除页面间残留的详情状态。
2. **首页与工作流执行中心。** 首页先处理行动和继续工作。运行概览优先列阻塞/异常/待审；详情保留整体进度与节点分组，并让失败原因、产物、人审和会话入口快速到达。
3. **设计和画布工作区。** 压缩重复头部；节点库、历史列表、属性面板可收起；内容主区优先给导图、文档和画布。用多节点图验证适配缩放、平移和选中细节的可读性。
4. **UI/DEMO 工作区。** 去掉任务残留，明确项目、产品、构建版本；DEMO 让预览和构建列表在首屏并列出现，避免默认自动启动造成意外状态切换。
5. **统一质量页和密度规则。** Bug 页减少纵向头部占位；测试有真实项目、用例和报告后，再验证质量流程及响应式布局。

## 重构边界与数据风险

实机布局重设计之外，前期只读源码审查还发现需要先处理的领域一致性问题：产品设计正文与一致性报告可能共用文档键；同步保存可能丢失笔记身份字段；Markdown 镜像写入失败仍可能清理旧文件；全局 UI/DEMO 创建可能借用残留项目选择；运行记录与冻结图分两次提交，失败会留下概览不可见的运行。它们是写入/持久化风险，不是这次桌面布局检查复现的视觉问题，修复后应由隔离回归测试验证。

建议的阶段边界：

1. 记录并保护当前未提交工作、代表性项目和运行数据；修复上述写入一致性与显式归属契约。
2. 抽出统一工作台外壳、页面注册和项目上下文；先完成首页与运行处理主路径。
3. 逐页迁移产品设计、UI/DEMO、质量与资料能力，旧 API 和数据保持兼容。
4. 每个阶段用同一组真实项目和运行检查视觉层级、返回路径、来源归属、保存与恢复；不把自动化验证当作人工验收。
