## 1. 目标与职责

让用户从已有图片或基准角色图得到可预览、可编辑、可采用的游戏素材，保留来源、参数、检查报告和历史版本。优先实现本地加工与静态 PNG 候选，再支持动画图集，随后接受控模型生成和可选视频工具。

| 组件 | 职责 |
| --- | --- |
| CCGS 角色 / 游戏简报 | 提供风格、角色、动作和验收约束 |
| DrawAI / 文件导入 | 提供基准图、参考图或已有素材；不作为本地文件路线的必需依赖 |
| sprite-gen 适配器 | 执行允许的加工 / 生成命令，提交成品与报告 |
| ComfyUI 适配器（后续候选） | 执行已登记的生成 / 加工工作流，将异步结果归一为素材候选；实际能力接入时验证 |
| Game Studio | 素材候选、工程使用、构建、试玩与导出 |
| 工作台共享内核 | Attempt、输入冻结、快照、编辑副本、采用、失效、权限与费用 |

接入方式采用固定版本的外部 Python 工具与受控子进程适配。图像处理算法不在首期翻译为 TypeScript；工具可选安装、按需调用，不能使工作台启动或基础游戏流程依赖 Python、模型登录或视频组件。

上述子进程方式适用于 sprite-gen。素材节点和产物类型保持后端无关，后续 ComfyUI 通过独立服务适配器接入；它可直接生产候选，也可与 sprite-gen 后处理串联，不能要求先成为 sprite-gen 内置 provider。

## 2. 最小流程与节点

```text
已有图片 / 基准图 + 素材用途与尺寸
  → 导入并记录来源
  → 本地加工，或显式配置的生成
  → 检查候选与预览
  → 用户编辑确认（挑选 / 编辑，确认时烘焙、捕获并验证成品）
  → 写入素材槽 / 动画资源
  → 构建与真实预览
```

| 节点类型 | 输入 → 输出 | 执行及审核 |
| --- | --- | --- |
| `asset.import` | 文件 / 参考图与许可说明 → 源素材清单 | 本地读取；校验类型、大小、hash 和产品范围 |
| `asset.process` | 冻结源素材、加工参数 → PNG / 图集与检查报告 | 本地转换；先支持抠图 / 切片，逐项启用其他命令 |
| `asset.generate` | 已采用参考图、风格 / 动作和执行配置 → 原始生成候选与收据 | S3 后启用；网络 / 费用受控，合法输出系统采用，推荐模板后接人工节点 |
| `human.edit-confirm`（素材配置） | 候选与检查报告 → 已确认的成品集合 | 先独立挑帧网页；保存不采用；确认冻结 revision，烘焙 / 捕获 / 校验成功才确认并继续 |
| `asset.export` | 已采用成品集合 → 导出文件集与 manifest | 自动本地导出 / 校验；不要求隐式二次人审，不直接读取可变草稿 |

上述为带人工节点的推荐模板，`asset.review` 是早期草案名称，统一映射为 `human.edit-confirm` 的素材编辑配置，不保留第二个人审协议。编辑副本、成品烘焙 / 捕获、快照发布、人工采用仍是不同操作，确认失败保留工作副本。没有人工节点时仅允许消费可自动获得并校验的成品，不能等待不存在的挑帧结果，也不能将未经挑选的原帧假称人工 curated；类型不兼容须阻止模板发布或执行。模板配置见 05；首期只注册实际支持的节点和参数，不将全部 CLI 命令自动开放为节点。

## 3. 产物与消费契约

下列为游戏产品包内拟注册的类型，最终 schema 在 S1 / S2 实施时发布版本；基础快照和文件清单沿用 02 / 08。

| 类型 | 必须保留的信息 | 消费方式 |
| --- | --- | --- |
| `asset-source` | 文件引用 / hash、原始名称、来源、参考关系、许可状态 | 只读输入，许可不明可处理但不得默认为可分发 |
| `asset-image` | 成品 PNG、宽高、alpha、用途、检查结果、来源 / 工具版本 | Game Studio 静态素材候选与显式采用 |
| `sprite-atlas` | atlas PNG、原 manifest、帧矩形、状态、时长 / fps、loop、hash | 独立图集消费者，禁止走单图 fitSprite 缩放 |
| `asset-check-report` | 对应产物版本、检查项、pass / fail / not_assessed、预览证据 | 技术校验与人工视觉结论分开保存 |

每个成品集合记录产品、operation / task、可用时的 run / node / attempt、输入版本与指纹、工具 / 适配器 revision、参数、导出 revision、文件 hash 和来源许可。模型生成另保存 requested / effective 执行身份、费用收据及估算状态。密钥不进入产物或浏览器。

成品读取规则：单帧使用 `export-pngs` 导出的 `curated/`；动画使用合成后的 atlas 与 manifest。不能把挑帧前 `frames/` 当最终交付。静态图的槽位适配应记录变换与成品 hash；图集需专用布局校验和播放适配，不允许独立缩放 PNG 后继续沿用旧坐标。

S2 首个消费者选择 Web Canvas，核验帧矩形、时长与状态切换。Aseprite-compatible JSON 作为可选导出，不能把导出字段校验当成 Phaser / Flame 真运行通过；Unity / Unreal 导入、切片和编辑器桥接另立范围。

## 4. 执行、编辑与发布

1. 适配器探测明确的 Python / 工具路径和版本、依赖、支持命令，冻结本次输入及配置。`capabilities` 仅用于发现与兼容性对照，执行仍由宿主白名单决定。
2. 自动 Attempt 使用独立 staging；只读输入与输出范围分离。历史快照不得作为可写 run-dir，也不能交给可能修复缓存的生产入口直接打开。
3. 人工编辑建立专用工作副本，关联候选基准、Draft revision 和工具 runRevision。两种 revision 各自校验；保存 / 导出遇到并发或基准变化时报告冲突，不能覆盖用户改动。
4. 导出时锁定工作副本 revision，串行执行成品烘焙和捕获。宿主验证必需文件、hash、schema、尺寸 / alpha、图集矩形 / 时序后，按共享发布协议创建不可变候选；导出失败保留原候选及编辑副本。
5. 独立模式由用户采用后回写；工作流模式由声明的发布目标执行：带人工节点时绑定其人工采用输出，无人工节点时可绑定已校验的系统采用成品。两者都先比较槽位 / 工程基准 hash，有外部修改则阻止覆盖并允许导出新副本；按采用关系传播下游 stale，不绕过既有权限。
6. 中断、取消、迟到结果、重启和外部效果按 03 对账。工具本地锁不替代 Attempt 租约与平台发布事务；禁止以退出码 0 或 QA 分数直接认定业务通过。

S1 的独立 Game Studio 模式可以复用 P1 已有候选 / 采用 / 版本接口，明确记录其工程版本和操作来源；平台工作流模式才使用 W1/W2 的 Attempt / 快照 / Adoption。两种入口共享素材适配服务，并检测同一槽位基准冲突，不为独立操作伪造 WorkflowRun。

## 5. 能力、费用与依赖边界

纯本地配置只允许已验证的抠图、切片、导出等命令，禁用网络和生成凭据。换色、平铺、阴影可在该配置下逐项验证后启用。原 curation 网页有 reroll / 补帧等模型入口；未完成 S3 时，必须在服务端禁用这些操作并隔离生成凭据，不能只隐藏按钮。若无法限制，退回只读预览与文件导入。

S3 根据 13 增加独立生成执行配置与实际收据。工具内置 CLI、登录读取和会话解析需逐项核验；若复用 codex 提供方，明确会话留存策略，验证 `--keep-session` 和审计捕获。缺配额 / 能力时不静默切换提供方；结果不明不自动重复购买。自由 `--provider-command`、无限修正循环不作为节点配置。

S0 按包元数据验证 Python 3.11+、Pillow 与 NumPy，使用独立环境；Windows 明确使用环境解释器，不依赖当前默认 `python`。S4 单独探测 ffmpeg、img2webp、RIFE / 模型与设备能力，控制输出数量、时长、磁盘和调用预算；基础素材功能不自动下载这些组件。

分发时保留 Apache-2.0 LICENSE、NOTICE 及相关来源 / 修改记录。参考图、生成素材、权重和外部二进制分别记录许可；代码许可不能代替素材分发许可。S3 / S4 的实现规划不授权实际付费调用或公开发布。

## 7. 风险与回退

工具缺失或升级不兼容时关闭自动处理，保留手工素材和历史产物；不自动迁移或重新加工已采用快照。挑帧网页先独立运行并限制到本地地址与对应产品工作副本，接入时验证写入范围和网络操作控制，嵌入 UI 后续单独估算。

S1 失败回到 P1 手工候选；S2 失败保留已有静态素材与原图集下载；S3 失败继续本地处理与外部成品导入；S4 失败不影响静态和图集路线。回退关闭入口、停止新领取并对账运行，不删除原文件、编辑副本、工程版本或历史收据。

## 8. 后续候选：ComfyUI 服务适配

### 8.1 与平台工作流的关系

工作台编排产品步骤、审核和版本，ComfyUI 工作流作为 `asset.generate` 或已验证的 `asset.process` 执行实现；节点内部图不直接转成工作台的节点 / 连线，不因此提前实施 W6 自由 DAG。相同输入输出契约允许选择 sprite-gen、ComfyUI 或外部成品导入，切换后端需冻结新配置 / 尝试并保留实际来源。

建议组合为“工作台冻结参考图与参数 → ComfyUI 执行已登记模板 → 捕获原始产物 → 可选 sprite-gen 抠图 / 切帧 / 图集 → 检查与人工采用 → Game Studio”。如输出已符合素材契约，可直接进入候选，sprite-gen 加工不是必经步骤。

### 8.2 预留适配契约

以下是工作台拟定接口，不代表已核验某版 ComfyUI API。具体请求、事件、任务标识及停止语义在接入 Spike 中按目标实例验证，不在计划中写死端点或版本。

| 契约 | 预留内容与约束 |
| --- | --- |
| 后端发现 | 实例连接引用 / 身份、版本、能力、适配器 revision；本机 / 远程部署接入时选择，缺能力显示 unavailable |
| 模板登记 | 可执行工作流表示及 schema、版本 / hash、依赖节点与模型清单；区分编辑器文件和实际提交格式，导入后需兼容性验证 |
| 参数映射 | 将提示词、参考图、尺寸、seed 等已声明业务字段映射到模板节点 / 输入；校验类型 / 范围，冻结渲染后的实际请求与 hash |
| 运行生命周期 | submit / observe / collect / requestCancel / reconcile；保存宿主 operation / Attempt、提交意图、实例身份、外部 job ID（若有）和当前可观察状态 |
| 产物捕获 | 将结果复制 / 下载至 staging，验证文件类型、数量、尺寸、hash 和来源，再转成共享 asset 产物；远端路径 / URL 不能充当正式快照 |
| 执行证据 | 保存请求及实际可观察的模型 / checkpoint、VAE、LoRA、采样参数、seed、节点 / 模板版本、输出节点与文件关联；无法读取的值明确 unknown，不冒充已验证 |

实际执行模型单独记录，不能将配置中的角色或文本模型名称当作图像模型身份。相同 seed 只作为复验参数；依赖、设备与实现差异可能改变结果，除非实测建立保证，不承诺逐字节重现。

### 8.3 任务恢复、共享实例与权限

提交前持久化意图，取得外部任务标识后立即关联。若提交响应丢失或宿主重启，先查证是否已受理；服务不能可靠关联时进入 `outcome_unknown`，不因连接重试自动重复生成。进度事件是观察信息，完成仍需校验输出并发布候选；迟到结果不能改变已取消 Attempt 的采用状态。

取消必须探测任务作用域。若目标实例只支持影响共享执行的停止操作，平台不能用取消单个 Attempt 的动作中断其他产品 / 用户；未验证独立取消前，可限制为受控独占 worker，或仅停止后续调度并等待 / 对账，界面显示未确认停止。

配置由宿主保存连接与凭据引用，浏览器和模板不包含密钥。模型、LoRA、自定义节点及其许可单独登记；导入工作流不自动安装节点、下载权重或扩大读写 / 网络权限。执行只开放已登记且验证的模板、参数和节点依赖；共享后端的文件、输出和事件需验证跨产品隔离。

本地模式应区分“宿主到本机服务的必要连接”和“服务内部访问外部网络”。节点或服务的网络、文件能力未经验证时不能宣称离线或已隔离；需要时采用受控 worker。预算包含时间、任务数、输出大小、GPU 配额或远程费用；无实测费用时显示 estimated / unavailable，不把本地推理写成零成本。

### 8.4 候选任务与启用门

候选任务在 11 中使用 S3-C01–S3-C03，只有实际排期接入后才进入该扩展验收；不追加到已有 S3 “至少一个提供方可用”的出口。图像生成接 S3，动画 / 视频按实际用途再依赖 S2 / S4。

先验证一个固定模板的“参数绑定 → 提交 → 进度 / 结果 → 产物捕获 → 人工采用”，再验证断线 / 重启去重、共享实例取消范围、模型 / 节点缺失与配额。失败时禁用 ComfyUI 适配，继续使用已验证后端或手工导入，保留历史候选和收据。
