# 06 游戏工作流与插件适配

状态：规划草案。依赖：W1/W2 内核、05 包契约、游戏 P0/P1。基础画布依赖游戏 P2。

## 1. 目标与范围

CCGS 提供流程 / 角色参考，Game Studio 执行小游戏工程操作，DrawAI 编辑设计与视觉产物，工作台保存流程状态和任务关系。各来源固定版本并记录修改，不能直接启动原仓库 Hook。

sprite-gen 纳入可选素材后端，提供本地加工、静态素材与动画图集生产。接入契约和独立 S0–S4 分期见 [15 素材工作流](15-asset-workflow-sprite-gen.md)，不增加游戏 P1 / P1.5 的基础出口。

首个可运行目标为 Web 小游戏；Unity / Unreal 编辑器、引擎工程生成、多人网络验证、视频制作和公网发布分别立项。

## 2. 与既有游戏分期的映射

| 原分期 | 本文使用方式 | 独立验收 |
| --- | --- | --- |
| P0 宿主适配 | 版本、项目范围、路径和资源探测 | 不增加流程角色和简报实现 |
| P1 游戏核心 | 创建 / 导入、构建、手工素材、预览、版本、导出 | 可关闭流程独立使用 |
| P1.5 流程层 | 本文的角色映射、简报、审核、交付卡 | 单独估算，依赖平台内核 |
| P2 画布 | DrawAI 挂载、保存、导出、素材候选桥接 | 不强制视频依赖 |
| P3 协作 | 自动试玩、测试 / Bug 完整联动 | 不并入 P1.5 |
| P4 媒体 / 发布 | 音视频、分享、公开发布 | 独立依赖 / 许可 / 费用验收 |

W4 是平台产品包阶段，不是把上述所有分期合成一个工期；共享快照和编辑器成本只计一次，插件特有改造单独列任务。

## 3. 最小模板和产物

```text
创意与约束
  → 生成一页简报 → 用户编辑确认
  → 玩法规则与验收 → 用户编辑确认
  → 构建候选 [等待检查]
  → 机器检查摘要 / 人工检查任务
  → 用户编辑确认（试玩反馈与采用）
  → 本地导出 [用户发起]
```

素材计划、素材更换、DrawAI 玩法图先作为可选步骤插入“规则 → 构建”之间；复杂反馈循环采用“基于已确认版本新运行”，MVP 不做循环边。

以上人审位置均为显式 `human.edit-confirm` 节点，是推荐模板而非自动节点内置门。可配置不含人审的模板，机器校验通过后自动继续；未实际试玩的构建不得因此标记 human-played。主动本地导出仍按用户选择或预先授权执行。

素材路线为“导入 / 基准图 → 本地加工或受控生成 → 人工编辑 → 成品导出 / 校验 → 采用 → 构建”。S1 先接静态候选，S2 增加动画图集；文件路线无需等待 DrawAI P2。关闭素材工具后仍可使用模板和手工素材完成基础游戏流程。

| 节点 | 输入 | 输出和验证 |
| --- | --- | --- |
| game.brief | 想法、Keep / Avoid、参考 | Markdown；范围和第一分钟明确，未知项有标记 |
| game.rules | 简报 | 规则 JSON / Markdown；目标、控制、失败、胜利、检查项 |
| game.build | 已采用规则和工程基准 | 文件集清单、HTML、构建摘要；格式 / 资源 / 路径校验 |
| game.check | 构建快照 | 检查报告，明确设备 / 能力 / 未评估项 |
| human.edit-confirm（游戏反馈配置） | 构建与报告 | 人工反馈与确认；continue / pivot / stop 决策，机器证据只读 |
| game.export | 已采用构建 | 只含交付文件的清单、hash、来源和许可 |

用户在对应人工节点编辑规则、简报、素材清单或反馈；自动节点输出可查看，修改进入新的工作副本 / 候选。修改代码 / 工程要创建专用工作副本，不通过改报告文字“修复”游戏。

## 4. Game Studio 适配

- 保留 game.json、game.js、assets/ASSETS.json、.studio、dist 等格式。
- 工作台显式登记工程；隐藏目录不能依赖 shelf 默认扫描发现。
- 构建前冻结输入文件集；结果归档后才登记候选，历史快照不可直接作为可写工程根。
- 资源定位通过适配器，发布包中验证模板和 Three 路径。
- Windows shelf 路径断言已非沙箱复现，但实际 UI 影响仍待 P0；完整证据见既有游戏评估，本文不扩称功能故障。
- 默认手工素材 / 模板可用；付费生图在有明确调用范围和费用策略后另接。
- 静态成品复用 P1 候选接口；动画图集使用独立产物类型和播放器，不能走单图缩放并沿用旧帧坐标。素材编辑只操作工作副本，导出后发布候选，采用才回写工程。

## 5. CCGS 角色与提示词

默认预设为制作 / 主理人、玩法设计、玩法程序、美术 / 技术美术、QA，按任务启用；49 个角色仅作为来源库。

当前工作台提示词上限 4000 字符、单队 12 人、运行成员建议 3、功能候选 6；部分并发是软约束，实施时重验。全部原角色文件过长，应转短角色卡 + 版本化参考资料，导入前显示长度，不能静默裁剪。

Claude Code 的工具、模型名、技能注入和 Agent memory 不自动映射 DSH；每项给出可用 / 降级 / 未支持结果。游戏交付协议不能回落为 `workbench_idea_expand`。

## 6. 检查等级

| 等级 | 证据 | 不代表什么 |
| --- | --- | --- |
| build-only | 编译 / 资源校验 | 页面可玩或玩法正确 |
| input-smoke | 启动、输入、截图、控制台 | 趣味性 / 完整玩法 |
| state-autoplay | `__gameState` 和自动操作 | 确定性回放 |
| deterministic-replay | 固定时钟 / 种子 / 输入重放 | 真实网络手感 |
| human-played | 用户反馈及对应版本 | 所有设备全部通过 |

Game Studio 与 CCGS 步进契约不同，不通过重命名接口宣称同种子可重放。首期缺检查器时使用人工任务并明确 not_assessed。

## 7. 任务与验收

- G01：角色转换、简报、规则、反馈和报告 schema。
- G02：游戏工作流模板、最小配置、工程 / 版本关联。
- G03：Game Studio staging / 快照 / 本地导出桥接。
- G04：P2 后接画布副本和 SVG / PNG → 槽位候选，采用前校验大小 / 透明 / 许可。
- G05：P3 接自动检查报告与 Bug，不以截图替代玩法验证。
- G06：完整跑通“简报 → 修改 → 规则 → 构建 → 试玩 → 回退 → 导出”；无生图服务仍可完成。

sprite-gen 本地验证、静态桥、动画、生成与媒体任务统一列入 11 的 S0–S4 工作包，不计入 G01–G06 已有范围。DrawAI 画布到素材的入口仍按 G04 / P2 验收。

## 8. 风险与回退

构建失败保留规则与工程基准；插件缺失节点转人工 / 不可用；画布未接好用文件引用；退出流程可回到 P1 独立工程操作。回写工程前校验基准 hash 和范围，有冲突只导出新副本。不可用生图和视频能力不计为首期已交付功能。
