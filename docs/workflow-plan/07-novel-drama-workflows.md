# 07 小说与短剧产品包

状态：后续验证计划，W5 启动；不增加游戏首期范围。依赖：01 至 05 已经通过试点。

## 1. 验证目的

证明产品包可以扩展创作领域，同时保持领域产物结构。首轮只做文本和结构化数据，不接出版平台、真人拍摄管理或视频生成。

## 2. 小说最小模板

```text
题材、读者、篇幅与边界
  → 人物 / 世界设定 → 用户编辑确认
  → 故事大纲 → 用户编辑确认
  → 章节计划 → 用户编辑确认
  → 单章草稿 → 用户编辑确认
  → 一致性检查报告 → 用户编辑确认（章节与报告）→ Markdown 导出
```

首期每次运行一个选定章节，不一次并行生成整本。产物包含故事设定 JSON、人物稳定 ID、大纲条目、chapterId、正文 Markdown、检查报告。每章固定引用设定 / 大纲 / 前情版本；不能在读取时自动套入后来的人设。

改人物或大纲会使实际依赖它的章节 stale；首期按显式引用集合保守失效，不声称自动理解所有隐含影响。

## 3. 短剧最小模板

```text
一句话概念、受众、单集时长
  → 节拍表 → 用户编辑确认
  → 分集大纲 → 用户编辑确认
  → 单集场次卡
  → 台词 / 动作剧本 → 用户编辑确认
  → 分镜说明 / DrawAI 引用（可选）
  → 场次与素材清单导出
```

场次具有稳定 sceneId、episodeId、地点、时间、角色引用、动作、对白、预期时长与镜头要求。检查时长只给估计和依据，不能把估计当作实际成片长度。

首期一次处理选定集 / 场，集和场的批量展开属于 W6；视频制作是独立产品能力，不作为文本流程完成条件。

两份推荐模板的每个“用户编辑确认”都是独立人工节点，可发布移除它们的新模板；没有人工节点的路径校验后系统采用并自动继续。用户修改机器检查报告时只编辑意见 / 处理决定，不改原始证据；若修改正文，应重新运行绑定新正文的必要一致性检查。

## 4. 共性和差异

| 共用内核 | 小说特有 | 短剧特有 |
| --- | --- | --- |
| 版本、草稿、审核、来源、重跑 | 章节、叙述视角、伏笔、人物弧线 | 集、场、对白、动作、镜头和预算约束 |
| 输出 schema 与验证报告 | 文体与长篇连续性 | 拍摄 / 视觉可执行性、时长 |
| 本地导出、文件清单 | 章节顺序与整稿编排 | 场次 / 素材 / 分镜清单 |

可复用 Markdown 编辑器，但产品包必须提供领域预览和 schema。抽象失效时先改包契约，不在调度器加 `if novel / if drama` 分支。

## 5. 长文本与上下文策略

上下文使用当前已采用事实卡、范围内全文、前情摘要、引用 ID 和输入清单。摘要是带来源的派生产物，源变更后摘要 stale。设定记忆不依赖暂停中的记忆库；不要把所有历史内容无限塞入提示词。

读取不足、预算不足或缺前文要标注 not_assessed / blocked，不能把模型没有发现矛盾当成全文无矛盾证据。

## 6. 任务与验收

- N01：一套小说 artifact / node schema 与最小章节流程。
- N02：单章修改、差异、采用、前情引用和整稿清单。
- D01：短剧集 / 场 schema、场次卡、剧本与导出。
- D02：可选画布引用和媒体缺失降级。
- X01：两包共用同一运行 / 快照 / 审核 API，不复制数据库和队列。
- X02：设定变化时过期标记准确；选定历史版本重跑不串入最新设定。
- X03：同一个工作区可同时有游戏与小说，路径和产品权限不串。

## 7. 风险、回退与未决项

长文本质量无法只靠结构测试，需小样本人审；模型检查保留依据和不确定项。版权 / 来源和用户材料边界由产物元数据记录，未经用户发起不自动公开。包关闭后仍可查看 Markdown / JSON 和历史文件。正式引入前确认目标是长篇、短篇还是网文，以及短剧的集 / 场规模，避免以通用模板承诺所有生产需求。
