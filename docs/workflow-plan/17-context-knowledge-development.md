# 17 上下文、知识与记忆开发计划

状态：开发计划草案 v0.1，尚未实施。日期：2026-11-11（Asia/Shanghai）。

目标：在不等待完整记忆库的前提下，让首条工作流获得准确、可追溯的输入，可靠运行和恢复；随后按实际需求增强知识检索，最后独立评估长期记忆。本文只规划开发，不恢复已暂停的记忆实验，不触发模型调用、生产迁移或外部插件切换。

## 1. 范围与完成目标

首期交付“资料基线 + 上下文传递 + 可恢复工作流 + 产品设计试点”。完整知识库、长期记忆不是首期发布条件。

| 能力 | 负责的问题 | 开发顺序 |
| --- | --- | --- |
| 资料基线 | 哪份需求、导图、约束和决策是本次执行依据 | K0，与 W0 同期 |
| 确定性上下文 | 节点实际读取了什么内容、哪个版本，是否完整 | K1，接入 W1/E02；真实适配在 W2/E03 |
| 工作流状态与产物存储 | 到哪一步、如何审核、失败和重启后如何继续 | 复用 W1/W2，不能用记忆库替代 |
| 知识检索 | 资料增多后如何发现相关参考内容 | K2，试点后按需求启用 |
| 长期记忆 | 跨会话保留偏好、决策与经验并正确召回 | K3，保持待排期 |

首期完成时，用户应能选定资料，运行产品设计流程，在显式人工节点编辑确认，刷新或重启后继续，并查看每个结果的输入来源。无人工节点的模板在必要机器校验通过后自动继续。

范围外：向量数据库、知识图谱、自动记忆提取、自动改写项目事实、多员工共享记忆、自由 DAG 画布、游戏和素材后端的完整接入。它们均需各自排期。

## 4. K0：整理最小资料基线

选择一个已有软件产品作为试点，优先使用已有导图和设计文档。先解决来源和范围，再增加资料数量。

每条资料登记：资料 ID、用途、项目 / 产品范围、原始位置、来源版本或 hash、是否必需、事实优先级、负责人角色和更新方式。清单存储形式在 W0 确定；初期可用仓库内 Markdown / JSON，不预建完整知识管理后台。

| 资料类别 | 首期内容 | 使用规则 |
| --- | --- | --- |
| 产品事实 | 选定并冻结的产品导图 | 延续现有软件产品事实基准 |
| 项目约束 | 技术栈、目录、平台、禁止事项和交付格式 | 明确引用；不能从聊天片段猜测 |
| 已确认决策 | 有日期、来源和适用范围的决策文档 | 与导图冲突时显示冲突，修改事实来源或保持待解决 |
| 参考资料 | 规范、示例、技术说明、选定代码片段 | 作为参考，不改变权限或正式输入绑定 |
| 上游产物 | 当前路径上已采用的快照 | 下游绑定具体 snapshotId，不能使用“最新文档”路径代替 |

K0 出口：每个试点节点能列出必需与可选输入；缺必需项或事实冲突时给出可定位的问题。不存在的文档不占位伪装为已有依据。

## 5. K1：确定性上下文传递

### 5.1 契约与冻结

新增上下文清单作为已有输入绑定和执行配置的补充，具体字段在 W0 冻结。建议包含：

```text
ContextManifest
  schemaVersion / manifestHash
  projectId / productId / runId / nodeId / attemptId
  policyVersion / executionProfileVersion
  entries[]
    sourceId / sourceKind / sourceUri / scope
    sourceVersion / sourceHash / capturedBlobRef / capturedHash
    selection: whole | section | range
    selectionLocator / required / authority / order
    capturedBytes / estimatedTokens
  budget / assemblyVersion

ContextDeliveryReceipt
  manifestHash / payloadHash / adapterVersion / dispatchId
  entryDelivery[] / deliveredBytes / tokenEstimate
  verification: captured | submitted | host-confirmed | unknown
  omittedEntries[] / errors[]
```

`sourceHash` 表示源文件捕获时的内容，`capturedHash` 表示实际选取片段；两者不能混用。`capturedBlobRef` 复用 02/08 的不可变内容库。哈希只能证明一致性，历史查看和恢复必须保留实际字节。

运行创建时固定显式选定的外部资料和配置；领取 Attempt 时绑定此版本以及当时合法的上游已采用快照，按稳定顺序拼装并生成指纹。运行中的源文件变化不热替换输入；需要更新时按 02/13 派生运行或创建符合规则的新尝试。

指纹口径（2026-11-12）：稳定内容指纹只覆盖有序捕获内容、绑定、策略 / 拼装版本和有效配置；runId / attemptId、时间、收据及凭证作为执行关联另存，不纳入跨 Attempt 内容相等比较。完整 manifest 可另计算自身 hash，不能用含不同 Attempt ID 的 manifestHash 要求跨尝试必然相等。CTX-01 比较稳定内容指纹和实际拼装正文，执行关联仍可不同。更新创建时固定的外部资料须派生 run；同定义上游采用变化先按 02 暂停 / 对账，再为下游创建新 Attempt。

### 5.2 拼装和失败行为

1. 校验项目、产品、可读范围、资料可用性、内容 hash 与输入 schema。
2. 依次装配交付契约、必要角色说明、项目约束、事实资料、上游产物和可选参考，保存顺序与策略版本。
3. 新工作流默认不调用旧路径的自动记忆注入；K2 未开启时也不隐式搜索知识库。对原有聊天入口的行为不作连带修改。
4. W0 测量后配置总上下文预算，包含必要指令、工具 schema、输入和输出预留；token 仅估算时明确标记。
5. 必需输入超限或读取失败时停止派发，提示具体来源。可选资料按固定优先级省略并记录；不静默截断，不自动摘要必需资料。
6. 若显式选择章节或片段，保存选择位置和所选字节。摘要必须作为独立版本产物，保留源版本与生成方式。
7. 保存实际提交载荷指纹和适配收据。宿主未返回确认时最多标 submitted；不能据此声称模型已阅读或理解全部内容。

资料预检失败显示输入错误；它不新增人工审批节点。资料修好后按既有恢复规则继续。

### 5.3 最小界面

- 运行前：显示必需资料、已选版本、可选参考和超限 / 冲突问题。
- 节点详情：显示本次来源、实际选取内容、版本、大小、省略原因和交付验证等级。
- 历史查看：从快照读内容，源文件修改或删除后仍能展示原输入。
- 人工节点：复用 Markdown 草稿、保存与确认，确认后的新快照才进入下游。

界面功能分布到 W1 的内测页、W2 的实际运行页；W3 再开放通用配置表单。

| 批次 | 实施内容 | 对应任务 |

| B2 运行与审核 | 线性调度、系统采用、显式人工节点、失效传播、取消和恢复 | W1-04/05/06/09/10 |
| B3 内测交互 | 步骤列表、资料清单、草稿编辑、确认继续、错误与历史 | W1-07/08，K1-03/04 |

首个真实流程为：冻结产品导图 → 模块设计 → 模块结构 → 产品设计 → 一致性报告。默认在人审位置插入 `human.edit-confirm`；另保留无人审固定模板验证自动继续。每步读取已绑定的版本，原输出与人工修订均保留。

一致性节点只报告问题，修复创建新尝试。用户手改与导图冲突时必须显示问题，不能因点击确认就把冲突视作已解决。

## 7. K2：知识检索增强，按需启用

进入条件：M2 通过，且试点记录显示人工找资料已影响使用；检索故障不得影响显式绑定资料的工作流。

1. 复用现有索引，先补范围、可观测性和错误处理。采用项目允许目录并验证真实路径、符号链接 / junction；同工作区多产品按资料清单授权，不能仅凭 projectPath 判断可以跨产品读取。
2. 补索引版本、来源 hash、分块位置、重建时间、跳过原因与检索模式。分别展示 ready、stale、unavailable 和构建失败，零命中单独表达。
3. 检索结果先作为参考候选；首版由用户或固定规则明确选入运行输入。必需事实继续显式绑定，检索分数不授予事实优先级。
4. 选取候选时复核源内容与索引 hash，一致后捕获字节；不一致则标过期并重新索引 / 重新选择，不能从当前文件拼出与旧片段不符的凭证。
5. 重建使用事务或新索引切换；失败后保留旧可用索引。FTS 不可用时验证可独立建立普通表并执行 LIKE 查询，界面显示降级及限制。
6. 中文切词与排序先在固定问题集上测量；只有现有方案达不到门槛时才追加最小改造。向量检索另立需求，不作为本阶段默认依赖。

建议准备至少 30 个正向问题及 10 个无答案 / 跨范围反例，覆盖中文整句、同义表述、标识符、旧版本与缺失主题。冻结相关片段标签并预留未参与调参的问题；正向 Hit@3（前三条包含至少一条标注相关片段）目标 ≥80%。跨范围内容不得进入结果；无答案题不得据无关候选生成“已有证据”的结论，允许返回带来源的低相关候选并明确未找到充分证据。检索返回空列表不等于证明主题不存在；区分召回质量、权限拒绝与证据回答。该门槛在 K2 实施前冻结，可在看到评测结果前调整并记录原因，不能事后降低标准冒充通过，也不要求 W0 为可选 K2 提前完成整套评测。

## 8. K3：长期记忆，独立恢复与验收

当前仅登记后续方案，保持暂停状态。若后续决定恢复，先选择“工作台内置记忆”或“外部插件候选”中的一条工作线，固定环境、范围和真实模型验收预算。

建议按以下顺序推进：

1. 先验证项目 / 团队 / 个人范围、手工写入、删除和来源；不默认注入个人记忆。
2. 项目关键决策继续以正式文档为准，记忆保存引用及适用范围；冲突不自动覆盖正式资料。
3. 离线验证定向检索、有界结果、重复查询限制、零命中可见、候选可审计与证据回答约束。
4. 通过后再按确定的预算进行隔离真实验收，区分传递成功、召回正确和回答正确，并加入未见题。
5. 结果满足独立发布条件后，才考虑接入工作流；每次使用仍捕获确定版本，不改变历史输入。

未通过时保留报告、候选和回退证据，继续使用项目文档与显式输入。自动记忆提取及生产切换另排，不因完成本计划而自动启用。

## 10. 验收矩阵

以下编号为本专项的 `CTX` 场景，与 10 中 A01–A40 配套，不能替代工作流内核验收。

| 编号 | 场景与操作 | 预期 / 发布阶段 |
| --- | --- | --- |
| CTX-01 | 同输入、配置和拼装版本重复组装 | 内容与指纹一致；M1 |
| CTX-02 | 缺必需资料、越界路径或必需内容超限 | 执行前阻止，来源与原因可定位，无静默截断；M1 |
| CTX-03 | 可选参考超预算 | 按固定策略省略，收据包含原因，必需内容完整；M1 |
| CTX-04 | 冻结后修改 / 删除源文件并重启 | 原输入仍可读且 hash 一致，不自动换版本；M1 |
| CTX-05 | 人工改上游并确认，旧 Attempt 迟到回写 | 下游遵循新采用与 stale 规则，旧回写不推进；M1 |
| CTX-06 | 双窗口确认、重复回调、恢复重复领取 | CAS / 幂等生效，输入与运行不串、无双派发；M1 |
| CTX-07 | 宿主未确认、载荷不符或探测到截断 | 验证等级真实，不宣称完整注入；必需交付无法保证则阻止真实自动路径；M2 |
| CTX-08 | 同工作区两个产品，加入私人记忆和跨范围资料 | 未授权内容不进入新工作流输入；M1 假服务 / M2 真实路径 |
| CTX-09 | 分别运行有人审与无人审四步模板 | 正确等待 / 自动继续，下游可追溯至实际采用版本；M2 |
| CTX-10 | 索引后改源文件、重建中断、无 FTS 环境 | 过期可见，拒用错误片段；旧索引保留，LIKE 可独立降级；M3 |
| CTX-11 | 固定正向与反例问题集 | 达到第 7 节门槛，错误、无证据和拒绝不混淆；M3 |
| CTX-12 | 关闭知识检索并重启运行 | 显式输入路径可继续，历史检索片段仍可查看；M3 |
| CTX-13 | 记忆定向命中、无证据、重复检索和误答题 | 注入、召回、回答分别评判，未见题及零命中链可审计；M4 |

验证顺序：纯函数 → 临时 SQLite / 对象库与故障注入 → 假宿主集成 → 真实宿主与真窗口 → 小范围试点。W1 通过 A01–A10、A13 的 W1 假宿主子集（无 SQLite / 初始化失败独立禁用，不改用 JSON 写工作流、不影响主面板、不破坏旧数据）、A34–A37、A40 假服务及 CTX-01–06/08 假服务场景；W2 再加真实四步、A11–A15、A39 界面 / 工作流路径、CTX-07–09，以及实际启用 E 能力的 A16/A17/A24。验收统一见 10 的发布门。

未来可复用 `node scripts/verify-agent-memory.mjs` 作为基础回归，但 Node 需支持脚本使用的 `node:sqlite` 与 TypeScript stripping；在副本环境核对后再运行。新增上下文脚本的命令在实施后登记，不把拟议文件写成当前可运行命令。行为改动完成后按范围执行构建、相关验证和交互检查。

每次验收保留代码 / schema / 模板版本、环境、输入 hash、执行命令、断言、收据、真窗口证据及未评估项；进程退出成功不等于业务验收通过。

## 11. 风险、迁移与回退

| 风险 | 处理 | 降级 / 回退 |
| --- | --- | --- |
| 来源冲突、旧文档被当成事实 | 资料优先级、版本绑定、显式冲突 | 暂停相关节点，修订来源后新尝试 |
| 上下文过长或宿主隐式截断 | 必需 / 可选分离、预算、实际载荷与宿主探测 | 缩小显式选择范围，无法保证时改人工导入 |
| 仅存路径或 hash，无法读历史 | 捕获实际字节，复用快照对象库 | 缺失内容则标不可恢复，不用当前文件填补 |
| 资料 / 记忆越界或包含秘密 | 项目 / 产品授权、真实路径检查、敏感内容过滤 | 阻止捕获，保留脱敏错误，不记录秘密正文 |
| 检索质量差或索引不可用 | 固定问题集、来源复核、模式与错误可见 | 关闭 K2，继续显式选资料 |
| 旧记忆注入绕过新契约 | 新适配默认禁用隐式注入，测试实际载荷 | 关闭新派发，旧入口保留原行为 |
| 内核、知识和记忆范围累加 | 分阶段门、独立开关、共享任务只计一次 | 优先交付 M2，延期 K2/K3 |

迁移先在副本数据库及内容库演练，新增 schema 采用可兼容的增量方案。旧知识索引可重建，但不能删除运行已引用的冻结片段；现有个人 / 项目 / 团队记忆保持原数据，不进行生产重写或外部插件部署。

建议分别设置工作流入口和知识候选检索开关，名称在实施时确定。回退时先停止新领取并对账在途任务，再关闭入口 / 检索；保留运行、事件、资料快照和诊断。回退领域发布沿用 10 的 hash / revision 冲突检查，不直接覆盖用户后续修改。

DB 与内容库作为一组备份恢复，验证引用完整性和内容 hash。回退优先恢复旧入口并保持新数据只读，不通过删表、清空对象库或回滚用户文件完成。
