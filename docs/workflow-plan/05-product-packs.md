# 05 产品包与模板

状态：规划草案。依赖：01、02、03、08。后续领域见 06、07。

## 1. 产品模型

Project 表示执行工作区；CreativeProduct 表示创作对象，含 `kind / name / projectId / packageId / metadata / archiveState`；Workflow 是可复用流程定义，Run 绑定某个产品和固定上下文。

现有 `products` 主要为软件设计壳。首期使用关联映射保留其语义，不直接为小说伪造模块 / mapId / Bug 项目，也不重复建三套工作区管理。是否扩展现有表或新增创作产品关联层由 W0 数据核对决定。

## 2. 产品包注册清单

```text
id / version / label / manifestSchema
productKinds[] / metadataSchema
artifactTypes[] / schemas[]
nodeTypes[] / executorAdapters[]
workflowTemplates[] / suggestedHumanNodes[] / validationPolicies[]
editors[] / previewers[] / validators[] / exporters[]
requiredCapabilities[] / optionalCapabilities[]
migrations[] / sourceRef / licenses[]
```

包内必须有一个最小示例和失败示例。MVP 为随应用发布的受信静态注册，用户不能靠模板 JSON 注入执行器脚本。后续外部包需独立安装和信任流程。

分期说明：W1 注册固定内核节点，W2 使用内置软件试点适配；W4-01 才将该最小注册边界扩展为可复用产品包与版本兼容注册。不能让 W2 为了加载软件试点先等待 W4，也不能把 W4 的游戏、多包和编辑器适配隐含放进 W1。下面的“用户调整节点、复制和发布模板”属于 W3，W1/W2 使用两份受控固定模板。

## 3. 核心与领域的边界

| 内核提供 | 产品包提供 |
| --- | --- |
| 版本、运行、状态和事件 | 简报、章节、场次、工程等领域含义 |
| 输入输出绑定、schema 基础校验 | 玩法 / 连续性 / 时长等业务验证 |
| 草稿、采用、失效和回退 | 领域编辑器、预览与导出格式 |
| 执行器接口、队列、配额 | Game Studio / DrawAI / sprite-gen / 引擎适配 |
| 审核与幂等协议 | 专业角色卡、按需参考资料 |

不要把软件导图的“事实基准”提升成所有产品必须遵守的规则；小说可用人物卡 / 大纲，短剧可用分集表和场次定义，各自声明权威输入及冲突策略。

## 4. 模板配置与发布

用户从模板复制得到定义草稿，可调整节点参数、模型 / 团队、输入绑定、人工门、可选节点；校验后发布不可变 WorkflowVersion。运行固定该版本和所有包版本。

人工门使用可见的 `human.edit-confirm` 节点；普通节点没有额外的隐藏内容审批。删除人工节点时必须将所有后继输入、最终输出和发布目标显式重绑至上游输出，通过类型 / 版本检查后才能发布。若产品包有强制机器校验或输出要求仍须满足，不能通过移除人审跳过。节点增删仅影响新版本 / 新运行。

模板修改与运行干预分开：在运行中改下一步参数必须派生新的配置版本 / 运行分支，不能静默改变历史计划。MVP 支持“从当前步骤复制为新运行并修改配置”。

模板导入清单包含 schema、包依赖、类型版本、默认配置及不含密钥的模型别名；未知节点显示占位并禁止执行，不能导入时丢掉连线。

## 5. 三类包的首期边界

- 软件设计包：四步文档流水线，复用既有项目、图、笔记和模块。
- 游戏包：简报 / 规则 / 工程 / 素材 / 试玩；引擎类型独立，图片槽不接受 Unity 包直接运行。
- 小说 / 短剧包：Markdown + 结构化 JSON；不默认上传出版平台或启动视频生成。

通用转换节点只在输入输出 schema 确定时复用；“任意内容变任意内容”的 AI 万能节点不作为默认产品协议。

游戏素材扩展按 [15 素材工作流](15-asset-workflow-sprite-gen.md) 分期注册 `asset-source`、`asset-image`、`sprite-atlas` 和 `asset-check-report`，以及对应编辑 / 预览 / 校验 / 导出适配。sprite-gen 声明为可选能力；缺失时保留手工导入和已有产物查看。CLI 能力发现不自动授予执行权限，也不将所有命令注册为节点；生成、动画与视频按各自 S 阶段启用。

素材类型与后端解耦，为后续 ComfyUI 服务适配保留相同输入输出契约；其工作流模板、参数映射与依赖清单单独版本化。ComfyUI 内部节点图作为执行器实现，不直接导入为平台编排图，也不要求经由 sprite-gen 才能接入。

## 6. 任务与验收

- P01：静态包注册器、类型冲突 / 版本兼容校验、能力清单。
- P02：软件试点包与 game 包最小示例；内核代码不含游戏提示词。
- P03：模板配置发布、复制、归档和导入导出。
- P04：缺包 / 缺 schema 的历史运行仍可按基础文件查看，但不能盲目执行。
- P05：卸载 / 升级不自动改历史运行；显式迁移创建新版本 / 运行。
- P06：通过 07 的小说 / 短剧试验，证明无须复制调度与快照实现。

## 7. 风险、回退与待确认

领域表膨胀时把可演进元数据留在有 schema 的 JSON 中，只有查询需要才建专表；不得失去 schema 校验。包兼容失败禁用执行但保留只读查看。包市场、签名、跨机器迁移在 W6 以后另立项目，本计划不隐含承诺。
