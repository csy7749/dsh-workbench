# 18 项目研习流程与开发计划

状态：规划草案 v0.1，尚未实施。日期：2026-11-12（Asia/Shanghai）。

来源：用户提出增加方便学习他人项目的流程，并认可“明确目标 → 项目地图 → 功能追踪 → 小实验 → 理解检查 → 沉淀与迁移”的方向，要求输出计划文档。本文将该方向转为实施建议；字段、接口、阶段估算与默认值仍需 L0 验证，不表示已完成开发或逐项获得外部执行授权。

目标：用户带着具体问题理解他人的项目，沿代码找到依据，通过适当实验核实理解，重开工作台后继续上次路线，并把适用的机制转成自己项目的候选任务。

任务状态唯一入口为 [11 第 15 节](11-roadmap-backlog.md#15-l-项目研习工作包)，验收唯一清单为 [10 第 8 节](10-testing-release-governance.md#8-项目研习专项验收)。本文负责产品行为、边界、契约建议和实施顺序，不另放任务复选框。

## 1. 产品目标与成功标准

一次研习围绕一个可回答的问题，例如：

> 学习这个项目如何管理 Agent 任务，重点看失败恢复，并判断哪些机制适合工作台。

用户结束一次专题研习后，应能找到关键代码、解释主要链路、说明已知限制，留下证据和后续问题。成功标准如下：

1. 从本地项目建立研习，记录目标、熟悉程度、时间预算与来源基线；无需先创建软件产品、Bug 或测试项目。
2. 地图、讲解和学习卡能定位至具体来源版本；明确已扫描范围、遗漏与未知项。
3. 关闭页面或重启后，恢复当前问题、已读位置、自己的笔记和下一步；无法恢复会话时仍能继续阅读。
4. AI 生成讲解、用户已读、自评理解、练习完成和实验验证分别记录。
5. 阅读默认只读；实验、安装、网络访问和应用目标的修改遵守各自授权范围。
6. 源码变动后保留旧记录，标记直接依赖及受影响后继，不把旧解释自动更新为新版本结论。
7. 借鉴建议包含适用前提、差异、许可来源和验证办法；用户选中后才能转为应用目标的任务或接入实验。

## 2. 用户入口与范围

### 2.1 三种研习入口

| 入口 | 适用目标 | 主要产出 | 阶段 |
| --- | --- | --- | --- |
| 快速了解 | 判断项目解决什么问题、是否值得深挖 | 项目地图、核心机制、建议路线 | L1 |
| 专题深挖 | 理解一个具体功能、设计或失败路径 | 功能链路、代码讲解、问题与学习卡 | L1；实验与练习随 L2 |
| 借鉴迁移 | 判断机制是否适合自己的项目 | 适用条件、目标差异、最小接入实验 | L3；L1 允许手工记为候选想法 |

创建时选择学习对象、输入目标，按需填写技术熟悉程度和投入时间。系统提出可编辑路线；探索中可追加问题、跳过基础、展开某段代码，再返回原路线。时间预算用于控制扫描、讲解和调用，不宣称能保证在该时间内学会。

### 2.2 必须分开的三个对象

| 对象 | 含义 | 关联规则 |
| --- | --- | --- |
| 学习对象 SourceProject | 他人的源码目录及其版本 | 可被多个研习引用；读取范围单独授权 |
| 研习 LearningStudy | 本次目标、路线、证据、笔记和进度 | 可独立存在，可挂工作台统一项目；L1 一个研习对应一个主要源码对象 |
| 应用目标 TargetProject | 准备借鉴到的自己的项目 | 可选；关联本身不授予读写权限，也不默认复制外部代码 |

同一工作台项目可研究多个外部仓库；L3 对比可选择多个已建立基线的学习对象。外部目录不因成为学习对象而自动登记成当前执行工作区，不复用 `ensureProject` 的工作区归并语义创建业务容器。

### 2.3 首期包含与后续边界

L1 包含本地目录、可核查的项目地图、专题阅读与问答、代码来源、学习卡、手工进度、持久恢复和 Markdown 导出。非 Git 目录可用文件捕获与 hash 建基线；不强求 Git。

仓库地址先作为来源元数据。自动下载 / 克隆、私有仓库凭据、递归子模块、Git LFS 和外部讨论抓取均另行验证与排期；L1 可提示用户选择已有本地副本。首期不执行来源项目脚本，不建立完整 IDE、语言服务器或全仓精确调用图，不要求向量库、知识图谱、多 Agent 团队和长期记忆。

## 3. 六步研习流程

| 步骤 | 用户体验 | 输出与完成条件 |
| --- | --- | --- |
| 1 建立基线 | 选择本地目录、目标与阅读范围 | 来源清单、版本 / 文件 hash、预算及可用能力；读取失败有具体原因 |
| 2 项目地图 | 看入口、目录职责、典型链路和建议先读文件 | 有代码入口的地图、扫描覆盖与未分析项；部分分析可用但必须标明 |
| 3 功能追踪 | 沿用户操作 → 入口 → 核心处理 → 数据变化 → 输出阅读 | 链路步骤、解释、证据、疑问与下一步；允许分支探索并返回 |
| 4 小实验 | 先看计划和预测，再按权限执行并比较 | L2 的实验方案、实际输入输出、环境、结果与限制 |
| 5 理解检查 | 自己解释、预测结果、做练习或直接看解析 | L2 的回答、反馈、自评和是否跳过；模型评价只作辅助 |
| 6 沉淀与应用 | 整理学习卡，选择是否继续深挖或形成迁移候选 | 地图 / 学习卡 / 未解决项；L3 才执行跨项目对比及目标任务转化 |

步骤 4、5 可选，L1 仍能完成一轮纯阅读研习，完成时明确“未进行运行验证”。完成研习表示路线已结束，不证明掌握全部项目。

### 3.1 地图与代码讲解

项目地图优先回答项目用途、启动入口、核心模块、数据流和目标相关的阅读顺序。区分源码、依赖、生成文件、示例和测试；测试中的预期不能代替实际运行结果。

每段关键讲解包含：负责什么、输入输出、上下游关系、为何可能这样设计、边界与失败条件。源码通常只能支持设计推断；只有明确的设计说明或其他可引用材料，才归因为作者意图。目录扫描或文本检索发现的链路标为候选，跨语言动态调用无法静态确认时保留未知。

超大项目按目标渐进展开。保存列举文件数、成功读取数、跳过原因、大小 / 数量限制和扫描错误；达到上限要返回覆盖不足，不能称为完整分析。可选摘要独立成产物并保留来源，必需输入超预算时停止派发并建议缩小问题，不静默截断。

### 3.2 证据与学习进度

| 维度 | 建议值 | 含义 |
| --- | --- | --- |
| 解释依据 | source-supported / inferred / unconfirmed | 源码或文档支持、基于实现推断、尚未确认 |
| 运行证据 | not-run / observed / inconclusive | 未运行、有观察记录、结果不足以支持结论 |
| 个人进度 | 未开始、阅读中、已读、自评理解 | 用户可调整；不由 AI 输出自动升级 |
| 练习记录 | 未做、已回答、看过解析、已跳过 | 与个人自评和运行证据分别存储 |

这些维度可以并存。例如“源码支持 + 未运行 + 用户已读”，不能压成一个“已验证”徽章。只在证据实际覆盖的环境和条件下声称运行观察成立，其他情形仍需验证。

## 4. 界面与继续学习

门户增加“项目研习”入口，研习清单支持独立研习与当前项目筛选。详情先用三栏 / 抽屉组合，窄屏折叠，不以自由节点画布为首期条件：

| 区域 | 核心内容 |
| --- | --- |
| 路线区 | 学习目标、项目地图、专题问题、阅读位置与下一步 |
| 阅读区 | 来源版本、代码 / 文档片段、功能链路、讲解与证据 |
| 协作区 | 问答、自己的笔记、学习卡；L2 增加实验和练习 |

首页展示最近问题、最后阅读位置、已确认结论、待验证问题和建议下一步。对话可“加入路线”或“保存为学习卡”，保存时绑定使用的来源；AI 不直接覆盖用户已编辑正文。

“继续学习”先恢复持久对象、来源和用户草稿，再检查会话是否可用；可恢复时关联原 DSH 会话，不可用时通过显式选择的来源与有界摘要创建新会话，展示上下文缺失项。不复制完整消息库，不把聊天自动总结当成用户已学会。

当前代码跳转和历史片段查看分别提供。行号漂移时优先显示保存的历史片段；不得把新文件同一行号当作旧证据。宿主无法精确跳转时展示路径、符号和片段，并提供复制定位信息。

## 5. 数据与来源契约建议

以下是领域关联草案，L0 冻结 schema / DDL；共用快照、内容库、执行配置和事件协议沿用 01/02/08/13/17，不复制这些实体的实现。

| 领域对象 | 最小字段 / 责任 |
| --- | --- |
| LearningStudy | id、title、goal、mode、level、budget、ownerProjectId?、targetProjectId?、sourceBaselineId、当前路线版本、归档状态 |
| SourceBaseline | 来源根目录引用、仓库 URL?、revision?、dirty 标记、允许范围、捕获清单、覆盖与错误、捕获时间 |
| SourceReference | baselineId、相对路径、符号?、历史行区间、源文件 hash、选取片段 hash、不可变内容引用、资料类型 |
| LearningQuestion / Route | 稳定问题 ID、父问题、顺序、目标、依赖、来源引用、候选讲解及采用版本 |
| LearningCard | 问题、解释、依据类别、来源引用、限制、未解决项、用户草稿 / 采用版本 |
| LearningCheckpoint | studyId、当前问题 / 位置、个人进度、下一步、用户 revision、关联 sessionId? |
| ExperimentRecord（L2） | 方案版本、来源与实验副本基线、命令 / 工作目录、环境、权限引用、预测、执行关联、输出与结论 |
| ExerciseRecord（L2） | 题目版本、关联问题 / 来源、用户回答、解析、反馈、跳过记录 |
| TransferCandidate（L3） | 来源机制与许可、目标基线、前提与差异、候选方案、验证办法、关联任务 |

规则：

1. Git 提交号不代表脏工作区实际内容；读取时记录文件 hash 与选取字节，非 Git 目录使用同样规则。
2. 基线包含所选范围的文件指纹清单，使用过的证据另捕获内容；未捕获文件不能声称可重放。读取前后变化导致清单不一致时重读或标不稳定，不虚构原子全仓快照。
3. 已捕获内容用于历史阅读。基线及引用清单不可变，切换来源版本创建新基线；旧学习卡与实验记录保持原关联。
4. 检索仅发现候选。选入上下文后捕获实际内容，记录本次交付，不直接把知识索引片段当作版本凭证。
5. 新讲解先成为候选，采用后才替换当前指针；用户草稿用 revision / CAS 防覆盖，迟到响应保留为历史候选。
6. 学习进度与工作流运行状态独立。无 runId 的阅读活动有稳定 study / operation 身份；接入工作流时才关联 run / node / attempt，不伪造执行记录。
7. Markdown 导出包含目标、基线、解释、来源、证据等级与未知项；绝对路径可脱敏，默认不打包整仓、凭据或原始日志。复制代码片段时保留来源及适用许可提示。

## 6. 执行、工具与权限边界

默认一个导师 Agent 负责阅读、讲解和路线建议。验证角色或多 Agent 只有在实际收益、能力与预算明确后另行启用；L1/L2 不依赖 C2。模型、角色、Skill、MCP 与工具范围复用 13 的请求 / 实际生效记录。

业务服务建议提供基线读取、来源片段读取、问题 / 候选提交、进度查询和学习卡导出；HTTP / DSH tool / 工作流节点按 03 使用同一服务。用户自评、人工采用与实验权限由可信用户通道表达，Agent 只能提交建议，不能伪造用户已理解或已授权。

| 操作 | 默认边界 | 能力不足时 |
| --- | --- | --- |
| 扫描 / 读取来源 | 允许根目录内的选定文本；排除密钥、依赖和生成目录；真实路径检查 | 只导入用户选取片段，不开放通用扫描 |
| 模型派发 | 仅所选范围；说明实际送入模型的资料及已有调用策略 | 人工导入解释候选；不标自动研习已接通 |
| 写笔记 / 学习卡 | 写研习存储，保留用户草稿，权限按所属研习检查 | 导出到用户选定位置，不改来源项目 |
| 实验（L2） | 独立副本；限定命令、工作目录、文件 / 网络 / 资源范围 | 保留实验方案，展示未运行 |
| 借鉴迁移（L3） | 只读比较；选定建议转任务；工程修改另走实施操作 | 导出建议，任务或代码变更未执行 |

来源仓库的 README、AGENTS、脚本和注释属于分析资料，不得改变宿主权限或导师指令。不能仅靠提示词保证只读；L0 验证真实文件 / 工具 / 网络边界，包括符号链接、Windows junction、跨目录引用和旧工具绕过。未经授权目录的内容不得捕获到学习存储或送入模型。

实验前展示命令、目录、安装依赖、网络需求和预期写入范围。已有有效授权可复用，不为每次阅读和保存重复确认；新增权限才请求授权。独立副本本身不能保证隔离，宿主无法限制时只提供计划。中断后展示真实执行状态，未知结果先对账，不自动重复执行脚本。

## 7. 独立研习与工作流接入

### 7.1 两条交付路径

| 路径 | 依赖 | 交付边界 |
| --- | --- | --- |
| 独立研习 L1 | L0、可用 SQLite / 内容存储、必要 K1/E 能力子集及只读执行证据 | 固定路线、阅读问答、学习卡、进度与恢复；不要求 W2 产品设计或 W4 包注册全部完成 |
| 正式工作流适配 L1-WF | L1、W1/W2 共用协议可用及该适配单独验收 | 使用现有运行、快照、采用和人工任务服务；先受信静态适配，不等待 W4 动态包注册 |

“可独立交付”表示入口和领域范围独立，不表示可以跳过持久化、来源和权限前置。若共用基础尚未实现，先完成 L0 和人工记录 / 导入路径；自动派发标为不可用。必需共用能力在原 W/K/E 工作包估算一次，L 只计新增适配，不能复制一套队列、对象库或 Agent runtime。

独立模式使用固定步骤和稳定 operation / 候选服务；后台任务若需要重启恢复，必须使用已经验证的共用持久执行能力。未具备该能力时，中断后保留已保存内容并由用户重新发起，不能假称恢复在途模型执行。

### 7.2 正式流程节点建议

```text
冻结目标与来源
  → 生成项目地图
  → 生成专题阅读路线
  → 追踪选定功能并交付学习卡
  → [可选实验：L2]
  → [可选理解练习：L2]
  → 汇总已知 / 未知与下一步
```

人工编辑确认需要显式 `human.edit-confirm`；无人工节点时合法产物系统采用后继续。练习是可选的领域人工任务，选用该节点才等待用户，可提交回答、看解析或跳过；用户的跳过记录不代表答对。只读模板不包含实验节点，不能因想验证问题就临时获得执行权限。

新增专题先成为路线候选，采用形成新版本；正在运行的路线、固定外部来源或配置变更遵守 02/13 的派生规则。源变更不能热替换在途输入。自动化学习步骤结束不修改个人“自评理解”。

## 8. 分期实施与估算

以下编号的任务状态只在 11 维护。每期独立估算、独立开关，不追加到 M1/M2 产品设计试点的原发布条件。

| 阶段 | 任务映射 | 交付与依赖 | 阶段出口 |
| --- | --- | --- | --- |
| L0 基线与契约 | L0-01–03 | 核对复用点，选脱敏夹具，冻结来源 / 进度 / 权限草案和估算 | 各能力有 verified / configured-only / unavailable 及继续 / 降级结论 |
| L1 能持续学 | L1-01–06 | 本地接入、地图、专题问答、来源、学习卡、继续学习和导出；依赖 L0 与已验证共用子集 | 一个专题从目标到成果结束，重启继续、历史依据与用户进度成立 |
| L1-WF 正式适配 | L1-WF-01 | L1 + 共用工作流协议，固定受信模板 | 有 / 无人工节点、版本绑定、取消及恢复单独通过 |
| L2 能动手验证 | L2-01–03 | L1 后增加隔离实验、可选练习、执行与未知结果恢复 | 预测与观察可对照，失败可保留，不能越权或重启重跑 |
| L3 能比较和迁移 | L3-01–03 | 多来源对比、基线变化影响、目标差异与任务转化 | 同一问题比较有证据；迁移建议有前提；转任务幂等 |

L1 只检查已引用文件相对基线是否发生变化，保留旧内容并提示重建基线；L3 才提供批量更新、影响传播视图和多版本比较。基础来源一致性不推迟到 L3。

L0 先记录能力与风险，不承诺全模块总工期。估算逐项包含 Host / 数据、Client、宿主适配、评审、真实窗口、备份和回退工作，给出最可能 / 保守人日与置信度。优先保持一个主开发批次；L 的排期由用户后续选择，不自动替换已有 M0 → M1 → M2 主线。

## 9. 首个试点与证据

建议从用户指定的一个本地项目中选择一个小专题，例如任务恢复或插件注册，限定几个核心文件与一个入口链路。L0 可先使用脱敏本地夹具，真实试点目录在启动时确定，不在本文假设任何外部仓库已经可读或能运行。

夹具应覆盖正常链路、文档与实现不一致、一个没有证据的问题、未提交修改、来源缺失 / 变化、链接逃逸和两个研习的隔离。人工基准列出关键入口、预期证据与可接受未知；评价答案正确性和依据是否支持结论，不能只统计引用数量。

L1 验收材料包括实际来源清单与覆盖、上下文收据、地图 / 学习卡、人工评判、保存与重启窗口证据、未验证项；L2 再增加隔离探测、命令与环境、观察输出、取消和未知结果对账；L3 增加不同项目 / 版本的对比依据和任务幂等记录。

自动检查只验证存储、来源定位、隔离、幂等、冲突和恢复等可断言行为；讲解质量及用户能否顺利继续学习需要人工场景验收。真实模型验收先固定试点、调用上限与授权，不复用旧记忆实验预算，不因本计划恢复记忆工作。

## 10. 风险、回退与待定项

| 风险 | 应对与可用退路 |
| --- | --- |
| 生成长文却没有解决学习问题 | 以问题 / 功能链路组织产物，标未知；人工评判首个专题 |
| 部分扫描被当作完整分析 | 输出覆盖、跳过与错误；缩小范围后继续 |
| 引用行号正确但内容不支持结论 | 捕获实际片段，区分依据 / 推断，使用人工基准检查支持关系 |
| 来源更新让旧讲解看似仍有效 | 不可变引用，基础变更提示，L3 传播影响；历史仍可读 |
| 外部仓库指令或实验脚本越权 | 将其作为数据，验证宿主实际边界；能力不足退回选段阅读 / 实验计划 |
| 自动总结覆盖用户笔记或伪造掌握度 | 候选 / 草稿 / 采用与进度分离，CAS，可信用户自评 |
| 阶段膨胀为完整 IDE / 记忆平台 | 锁 L1 单专题出口；实验、检索增强、跨项目迁移分别排期 |

L0 待定项：来源真实路径策略与文件配额、存储位置与 SQLite 初始化、宿主只读 / 代码跳转能力、候选与用户进度 API、模型预算默认值。L2 前另定实验执行后端、可限制的权限、依赖安装与未知结果协议；L3 前确定首个对比问题和应用目标。

回退先停止新派发并对账在途操作，再关闭研习或实验入口，保留学习卡、草稿、来源内容与历史只读。研习关闭不删除来源目录、实验副本或目标项目文件；清理数据需单独选择范围，并保护仍被学习卡引用的内容。备份恢复包含数据库、来源内容、用户草稿与执行关联；在副本演练，不直接重写生产库。
