# 10 测试、发布与治理

状态：规划草案。贯穿 W0 至 W6；每期按实际能力验收，不要求早期完成后续媒体或产品包测试。

## 1. 测试层级和证据

| 层级 | 范围 | 证据 |
| --- | --- | --- |
| 纯函数 | 状态、端口、schema、hash、失效传播 | 确定性断言和反例 |
| SQLite / 文件 | CAS、事务、blob 发布、GC、恢复 | 临时库和故障注入结果 |
| 执行器 | 队列、token、超时、中断、迟到结果 | 假执行器 + 目标宿主对接 |
| 交互 | 草稿、采用、差异、配置、刷新恢复 | 浏览器 / 真窗口操作记录 |
| 产品包 | 软件四步、游戏、小说、短剧 | 各自 schema 与样例验收 |
| 人工产品验收 | 游戏手感、文本审稿、分镜可执行性 | 对应快照版本的人审意见 |

记录代码版本、模板版本、包版本、OS / Node / DSH profile、是否沙箱、输入快照、命令、结果和未评估项。测试无法启动和断言失败分开；已有 shelf.test 结果不能替代真实 DSH UI 验收。

## 3. 权限和信任

每次运行明确可读输入、工作区写范围、可用模型 / 工具、网络和费用策略。模板资料、第三方指令、网页、小说文本等均为输入数据，不具备修改权限策略的权力。

硬校验包括路径、文件类型 / 大小、schema、密钥检查和执行器信任；业务审核包括玩法或文风建议，两类不能混淆。原插件已存在工具可能绕过工作流发布机制，必须验证会话工具范围，不只增加专用写回工具。

付费生成、网络下载、公开发布、删除 / 覆盖等沿用用户已授权的范围；确需新增授权时集中展示目标和影响，不能因模板写着“自动提交”而自动取得权限。避免把每次保存草稿也变成权限确认。

## 4. 资源与成本

记录模型调用、时长、尝试次数、内容库占用和外部费用收据；无可靠计费数据时显示 estimated / unavailable。默认限制自动重试、总运行时间、单文件与输出数量；具体上限 W0 量测后配置化。

事件 / 输出日志有保留和脱敏策略，不保存密钥或默认把全部个人记忆放进运行包。人工等待不占执行并发，但占持久化记录。

## 6. 回退演练

1. 停止新领取，标记运行暂停 / 待恢复，确认实际外部任务状态。
2. 关闭新 UI / 默认入口，保留历史只读和诊断导出。
3. 保留新增表与内容对象，恢复旧入口；不让旧客户端写新状态。
4. 若回退已发布领域内容，核对当前 hash / revision 与备份基准，变过则只导出恢复副本。
5. 在副本库演练完整 DB + 对象库恢复，再决定生产恢复；不直接删表或删对象。

## 7. 各期完成规则

交付物、约定的自动检查、适用的真窗口测试、已知限制、迁移和回退记录齐备才能标完成。模型调用或测试预算用完不代表通过；未验证项保持未评估。文档、API schema 和实现状态需同步，后续能力不追加到已冻结阶段的完成条件。
