# 02 快照、草稿与依赖

状态：规划草案。依赖：01。下游：03、04、05、08。

## 1. 快照与工作文件

用户修改的是工作副本；快照是可重现的不可变记录。现有工程文件可继续被编辑器修改，但历史运行必须读取内容库中的确定版本，不能仅保存“现在的文件路径”。

首期支持 `text / markdown / json / file-set / report`；图片、HTML、画布和游戏工程通过文件清单引用。媒体编解码、自动视觉合并不属于快照内核。

建议清单：

```text
snapshotId, artifactId, schemaVersion, artifactType
contentHash, manifestHash, blobs[{relativePath, hash, bytes, mediaType}]
parentSnapshotIds[], sourceAttemptId, inputSnapshotIds[]
authorType, authorId, createdAt, sourceVersion, licenseRefs[]
```

确认状态不写回 Snapshot；采用、替换、恢复和归档是外部关系 / 事件。相同字节可共用 blob，但不能因 hash 相同合并不同来源的快照身份。

## 2. 编辑与采用流程

```text
生成候选 S1（不可变）
  → 派生草稿 D1，base=S1
  → 保存 D1 revision 1/2/3
  → 校验该 revision
  → 创建人工修订快照 S2，parent=S1
  → 采用 S2，记录验证证据和输入集合
  → 下游绑定 S2，开始新尝试
```

用户可不改原候选 S1 的内容直接确认；人工节点仍创建自己的输出快照身份，引用相同 blob 并记录 parent=S1，不能把上游 Snapshot 身份直接当成人工节点的输出。AI 修订产生新候选 S3，不覆盖 D1。选择候选时展示父版本和生成时间。多文件输出以 OutputSet 作为完整性边界，缺一文件不能半套采用。

上述编辑链在显式 `human.edit-confirm` 节点执行。其输入是上游自动节点的已系统采用快照，编辑不会修改上游的 Adoption；确认后生成该人工节点自己的输出并绑定下游。未改内容也可确认，复用 blob 但保留独立的人工决策身份。普通节点不含人工步骤时，宿主校验后系统采用候选并继续，不创建空草稿要求用户点击。

编辑器中的“保存”只持久化草稿；“采用并继续”在内容准备完成后，以带 revision 的数据库事务记录采用和继续意图，文件发布仍按 08 单独对账，不能把这个按钮理解成文件与数据库跨系统原子提交。通过后仍可再次修订，产生新快照和采用关系。

同一运行内重新采用上游版本，必须先暂停并对账受影响的活跃执行；只允许既有定义 / 配置下、仍获授权的输入绑定更新，CAS 记录新采用并传播 stale，随后显式继续。更换运行创建时固定的外部资料、模板、配置、权限或修改终态运行时派生新 run。两种路径都不能改写旧 Attempt 的实际输入。普通节点的预览 / 草稿保存不会自动暂停或重新采用。

## 3. 上游修改与下游失效

每个下游 Attempt 保存实际消费的 snapshotId 集合和输入绑定版本。

| 上游动作 | 下游处理 |
| --- | --- |
| 只保存草稿、未采用 | 下游不变，显示上游有未采用草稿 |
| 创建新候选、未采用 | 下游不变 |
| 采用新版本 | 所有消费旧版本的后继 Step 标 stale |
| 下游正在运行时上游切换 | 本轮标记输入已过期；请求取消，迟到结果仅留为旧输入候选 |
| 历史运行 / 分支仍用旧版本 | 仍然合法，显示固定来源，不随当前指针更新 |

MVP 不提供“忽略过期并当作当前”的按钮。要保留旧下游，创建固定旧输入的分支；要采纳新上游，从第一个受影响节点重跑。跨领域字段级增量失效在后续做，不猜测改一个字是否影响玩法。

## 4. 重试、恢复和分支

- 相同输入重试：新 attempt，候选追加；允许比较效果和成本。
- 回退：从历史快照创建恢复采用记录；如要表达人工恢复原因，可创建内容相同的新来源快照。
- 运行未终结时切换采用版本：更新受影响后继，不重写已保存 Attempt 的输入。
- 已终结运行修订：新 run，记录 fork 起点；可复用前序已采用快照，仍校验包 / schema 兼容。
- 首期分支是运行级分支，非自由画布分支；不自动合并工程和媒体。

## 5. 差异与编辑能力

| 类型 | MVP 差异 | 后续能力 |
| --- | --- | --- |
| Markdown / 小说文本 | 标题、行、段落差异 | 专用连续性 / 角色引用比较 |
| JSON / 模块 | 稳定 ID 与字段差异，顺序明确 | 字段合并 |
| 产品导图 | 复用已有节点 / 边差异，验证格式 | 合并建议 |
| 图片 / HTML | 预览、尺寸、hash 和来源 | 视觉差异辅助 |
| 游戏 / 画布文件集 | 清单增删改与专用预览 | 编辑器内局部合并 |

差异比较从内容库读取；不能拿历史元数据与当前工作文件比较后伪称历史差异。

## 6. 资源生命周期

输出和编辑稿均有配额、大小上限和可见占用。被运行、草稿、采用或导出清单引用的 blob 不自动删除。回收先做候选报告、保留期和可恢复归档；不可变内容库不提供普通“清空缓存”入口。

外部工程首次快照只读捕获，拒绝秘密文件、依赖目录、符号链接和未允许路径。Git 忽略不代表不需要备份；Game Studio 快照也不能代替整个平台的快照。

## 7. 任务与验收

- S01：内容寻址 blob 和文件集清单，重新读出 hash 一致。
- S02：原候选 → 草稿 → 修改快照 → 采用 → 下一步全链可追溯。
- S03：只保存草稿不触发失效，采用新版本才触发。
- S04：运行中输入变化，旧回调不推进下游。
- S05：恢复和分支保留旧版本；删除工作文件后仍能查看快照。
- S06：多文件内部采用只呈现完整集合；正式文件发布故障明确显示逐项状态与待恢复，不把半套已发布显示成整套发布完成，不承诺外部文件的跨文件原子可见性。

## 8. 风险、回退与未决项

主要风险为占用增长、媒体漏捕获和外部编辑竞争。采用清单校验、配额、路径白名单和最终写入前 hash 复核；捕获失败保留原文件并停止采用。W0 确定大文件是否支持流式捕获以及默认容量，未验证前不承诺视频工程完整快照。
