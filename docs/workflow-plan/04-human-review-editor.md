# 04 人工审核与产物编辑

状态：规划草案。M0 冻结依据：`docs/evidence/workflow/m0/contract-human-adoption.md` 的 H-01..H-14；运行时确认、恢复和可信人工身份仍由 W1/W2 验收。依赖：01、02；与 09 共用交互约定。

## 1. 用户目标与范围

用户可以查看任一节点的输出；需要用户编辑确认的位置使用显式 `human.edit-confirm` 节点。运行到该节点创建持久待办并停止启动后继，用户可以编辑、保存、比较、要求 AI 修订，最后确认继续。没有该节点的路径在机器校验通过后系统采用并自动继续。MVP 复用笔记 / 表单能力；完整媒体编辑器通过适配逐步加入，不自建图片、视频或代码 IDE。

```text
需要人工：生成文档 → 用户编辑确认 → 提炼结构 → 后续自动节点
无需人工：生成文档 → 提炼结构 → 后续自动节点
```

节点允许检查后不改内容直接确认，不强制改一个字；人审是用户动作，不能由模型的“已检查”代替。运行中的普通节点不会因用户打开预览或保存一个旁路候选而等待；修改已采用上游按 02 先暂停、对账，再更新同一运行的合法采用绑定并传播 stale；改变固定外部资料、定义 / 配置 / 权限或终态运行则派生新运行，不能追溯修改已执行步骤。

## 2. 审核页面

| 区域 | 内容 |
| --- | --- |
| 上下文 | 产品、运行、人工待办、输入版本、当前候选、编辑说明 |
| 产物 | 输出清单、文件 / 文档编辑器、候选切换 |
| 验证 | pass / fail / not_assessed / not_applicable、原因、证据 |
| 差异 | 原始生成、当前草稿、上次采用版本的比较 |
| 操作 | 保存草稿、确认并继续、确认并暂停、要求修订、暂停 |

默认“确认并继续”完成当前人工节点并调度下一步；“确认并暂停”原子地完成确认并将运行暂停，避免下一步抢先启动。两者均显示将确认的 draftRevision 和受影响下游。运行已经暂停时，确认仅保存结果、不解除暂停。只保存草稿不确认、不推进；草稿不会自动成为默认输入。

## 3. 完整操作链

1. 上游自动节点完成机器校验和系统采用；运行到人工节点，创建绑定其输入集合的 HumanTask，进入 waiting_review。
2. 展示输入产物和检查报告；用户编辑时创建 Draft，保存带 revision；自动保存仅保存 Draft。不编辑时保留明确的原文输入版本。
3. 用户选择确认，客户端提交 HumanTask ID / taskRevision、输入指纹、expectedRevision、expectedAdoptionId、expectedRunRevision、继续 / 暂停意图和幂等 key。
4. 宿主重新校验该内容、输入新鲜度、schema 和验证报告是否过期。
5. 校验通过后创建人工节点的输出 Snapshot / human Adoption / Event，HumanTask 记 confirmed；按声明的目标发布，决定下游 stale 和是否继续。
6. 校验不通过则保留草稿，定位具体字段 / 文件；不能先推进再补错误。

人工修改后，原验证报告只有在绑定内容 hash 仍一致时有效；对新内容重新运行必要检查。用户修正测试报告文字不能改变机器测试结果。

刷新、关页、重启后恢复同一待办和最近已保存草稿；人工等待没有自动确认超时。上游基准被替换、取消或失效时禁用旧确认，保留草稿并展示差异；重新绑定须显式操作。确认后仍需后续人工判断时，应在模板中再放人工节点，而不是要求每个自动节点重复确认。

## 4. 修订、候选与冲突

- “要求 AI 修订”指定基准快照 / 草稿 revision、意见和保留项；输出新候选，不覆盖人工正在编辑的 Draft。
- 草稿 409 冲突展示服务器版本、用户本地未保存内容和恢复操作；不使用旧全量快照接口的“丢本地重载”方式。
- 真实工程文件外部变化：生成新的导入候选，提示差异；只改变文件路径不算快照更新。
- 多文件产物按集合采用，允许逐文档编辑，但未通过集合完整性前不继续。
- 用户主动驳回候选保留原因与产物，不等于运行取消。

[节点内协作聊天](14-chat-workflow-studio.md) 是“要求 AI 修订”的扩展入口，同样绑定基准 snapshotId / draftRevision，输出新候选并重新验证。聊天中的“大家同意”或主理人总结不能替代用户采用；多员工评审也不得直接改 Draft 或当前采用。该入口属于 C 增量，不是原最小编辑器的新增前置。

## 5. 编辑器契约

```text
canOpen(artifactType, schemaVersion)
open({snapshotId, draftId, readonly, workspaceContext})
serializeDraft() -> manifest / structured content
validateLocal() -> hints
dispose() -> release listeners / React roots / timers
```

局部验证仅给即时提示，最终校验在宿主执行。保存只接受受控内容和相对路径，不接受浏览器指定任意文件位置。

| 产物类型 | 首期 | 后续 |
| --- | --- | --- |
| Markdown / 文本 | 笔记式编辑、预览、差异 | 章节 / 台词专用编辑 |
| JSON / 模块清单 | schema 表单、结构预览 | 复杂树 / 画布 |
| 产品导图 | 冻结输入预览；编辑走现有版本入口 | 工作流内导图桥接 |
| 图片 / HTML | 沙箱预览、替换、元数据 | 专用视觉对比 |
| 游戏工程 | manifest / 文件清单、工程编辑入口 | 隔离可编辑工作副本 |
| DrawAI | 未接入时只读 / 外部打开 | 独立工作副本内挂载画布 |

## 6. 验收任务

- H01：保存 / 采用 / 继续三种动作可区分，接口幂等。
- H02：双窗口编辑冲突可保留用户文本，刷新后恢复最近已保存 Draft。
- H03：用户改文后原验证失效，必要验证重新执行。
- H04：AI 修订期间手改草稿不会被回写覆盖。
- H05：历史运行只读，派生新运行后才可修订与继续。
- H06：键盘可操作、窄窗可预览和确认，颜色之外有文字状态。
- H07：有人工节点则持久等待，无人工节点则合法输出自动推进；不修改内容也可确认。
- H08：确认并暂停不会抢跑，暂停期间确认不恢复运行，上游变更后的旧确认失效。

## 7. 风险、回退与待确认

人工介入位置直接体现在模板节点和输入绑定中。默认示例可带人工节点，用户可发布去掉它们的新模板；旧 `reviewPolicy: required` 的资料或导入定义须显式转换成人工节点并让用户核对，不保留隐藏审批，也不静默删除等待点。复杂编辑器未接好时只读 + 导出副本，不伪称就地编辑。未保存文本可用本地恢复缓存，但共享设备 / 敏感产品是否开启缓存需在 W0 确定；不能让缓存成为唯一保存机制。
